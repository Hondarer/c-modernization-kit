# 差し替え可能な関数の命名の考え方

## 位置づけ

この文書は、差し替え可能な関数と、それに関連するシンボルや設定キーの命名方針を、1 つの考え方として示します。  
この命名方針は、リポジトリの必須規則ではありません。  
シンボル名の接頭辞など、リポジトリ全体に適用する規則は [コーディング規範](../../general/docs/coding-guideline.md) を正本とします。

## 仕組みの性質

override-sample の仕組みは、処理の差し替えです。  
差し替え可能な関数は、設定ファイルで差し替え実装が指定されている場合に処理全体を差し替え実装へ委譲し、その戻り値をそのまま返します。  
差し替え実装が指定されていない場合は、既定の実装を実行します。

この性質は、C# のイベントとは異なります。

| 観点 | C# のイベント | この仕組み |
|---|---|---|
| 登録できる数 | 複数 | 1 つ |
| 戻り値 | なし | あり |
| 既定の実装 | 通知後も実行される | 実行されない |

そのため、通知を表す `on_` や `handler` を名前に使用すると、既定の実装が継続して実行されると誤解されるおそれがあります。

## 用語

この文書では、次の用語を使用します。

| 用語 | 意味 | override-sample での例 |
|---|---|---|
| 差し替え可能な関数 | 設定ファイルによって実装を差し替えられる公開関数 | `base_calc` |
| 差し替えキー | 設定ファイルで差し替え可能な関数を識別するキー | `"base_calc"` |
| 差し替え実装 | 差し替え可能な関数の代わりに実行される関数 | `override_calc` |

差し替え可能な関数と差し替えキーは、差し替えられる側のライブラリ (libbase) が決定します。  
差し替え実装は、差し替える側のライブラリ (liboverride) が決定します。  
名前を決定する主体が異なるため、それぞれの名前は定義元のライブラリの接頭辞に従います。

## 命名の考え方

| 対象 | 形式 | 例 |
|---|---|---|
| 差し替え可能な関数 | `<lib>_<動詞>` | `base_calc` |
| 関数ポインター型 | `<lib>_<動詞>_fn` | `base_calc_fn` |
| 差し替えキー | 差し替え可能な関数名と同じ | `"base_calc"` |
| 差し替え実装 | `<差し替え側のlib>_<動詞>` (必要に応じて `_<実装の特徴>` を付与) | `override_calc` |

設定ファイルの記述例は次のとおりです。

```json
{
  "base_calc": {
    "lib": "liboverride",
    "func": "override_calc"
  }
}
```

### 差し替え可能な関数

差し替え可能な関数には、通常の公開関数と同じ名前を付け、差し替え可能であることを名前に含めません。  
呼び出し側の観点では、差し替え可能な関数を通常の API と区別する必要がないためです。  
既存の関数を後から差し替え可能にする場合も、関数名と ABI を変更せずに対応できます。

### 関数ポインター型

関数ポインター型は、差し替え可能な関数を宣言する公開ヘッダーに定義します。  
差し替え実装を提供するライブラリは、この型を参照してシグネチャと呼び出し規約を一致させます。  
型に `BASE_API` などの呼び出し規約マクロを含めると、Windows で差し替え可能な関数と差し替え実装の呼び出し規約が一致します。

### 差し替えキー

差し替えキーには、差し替え可能な関数名をそのまま使用します。  
関数名とキーの対応表が不要になり、設定ファイルとソース コードを同じ文字列で検索できます。

差し替えキーは設定ファイルを介した外部との契約になります。  
差し替え可能な関数の名前を変更する場合は、既存の設定ファイルとの互換性を確認してください。

### 差し替え実装

差し替え実装には、差し替える側のライブラリの接頭辞と、差し替え可能な関数の動詞を組み合わせた名前を付けます。  
この命名により、どのライブラリがどの関数の差し替え実装を提供しているかを名前から識別できます。

1 つのライブラリで同じ関数に対する複数の差し替え実装を提供する場合は、末尾に実装の特徴を付与して区別します (例: `override_calc_product`、`override_calc_difference`)。  
差し替え実装が 1 つだけの場合は、実装の特徴を付与する必要はありません。

## 推奨しない命名

差し替え実装に、差し替え可能な関数と同じ名前 (例: `base_calc`) を付けることは避けます。  
差し替え実装の内部で同名の関数を呼び出すと、差し替え可能な関数に解決される場合があり、差し替え可能な関数と差し替え実装の間で無限再帰が発生するおそれがあります。  
これは、Linux では同名のシンボルが複数の共有ライブラリに存在する場合、解決される定義がロード順に依存するためです。

差し替えキーと差し替え実装に、`on_calc` のような同じ名前を付けることも避けます。  
両者を同じ名前に固定すると、設定ファイルの `func` で複数の差し替え実装から選択できなくなります。
