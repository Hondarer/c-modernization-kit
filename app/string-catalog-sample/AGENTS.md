# AGENTS.md

## 対象

この app は、文字列 ID、引数スキーマ、言語別の文字列リソースを分離して文字列を組み立てるサンプルです。  
`app/c-platform` の `cplat_trace_level` と `cplat_console_init/dispose` を利用します。

## 作業別の参照先

- 対象の目的と構成を確認する場合は [README.md](README.md)
- 要件と外部から観測できる振る舞いを確認する場合は [機能仕様](docs/functional-spec/README.md) の該当節
- 責務分離、書式の仕様、生成物の境界を変更する場合は [アーキテクチャー](docs/architecture.md) の該当節
- C の規範は [コーディング規範](../general/docs/coding-guideline.md)
- テスト構成は [テスト方法](../../framework/testfw/docs/how-to-test.md)

## 機能仕様の同期

`docs/functional-spec/` は、利用側から見た string_catalog の要件と振る舞いを説明する正本です。  
機能仕様は API 設計、実装、テストの入力であり、これらの下流成果物を根拠として記載しません。

外部から観測できる振る舞い、前提、保証範囲、適用範囲外を変更する場合は、同じ変更の中で該当する機能仕様を見直してください。  
要件 ID と UUID の形式、カテゴリごとの主語、下流成果物からの参照記法は [機能仕様の入口](docs/functional-spec/README.md) に従ってください。

機能仕様には、関数名、型名、定数名、引数と戻り値、公開ヘッダー、実装方式、テスト方法を記載しません。

## 変更時の制約

- 生成物は `prod/src/cmd/string-catalog-sample/gen/` へ置き、Git では管理しません。ビルドが `bin/string_catalog_gen.py` を駆動するため、手で実行する必要はありません。変更するのは `sample_messages.jsonc` です。
- 生成は app 直下の `makepart.mk` が makefile のパース時に行います。ビルド規則にしないでください。テストのディレクトリを解釈する時点で生成物が必要になるためです。
- 生成ヘッダーは `#include "gen/sample_messages.h"` の形で取り込みます。テストから引き込む場合は `INCDIR` へ `gen` を加えてください。
- `sample_messages.jsonc` がカタログ定義の正本です。形式は JSONC で、行コメント、ブロック コメント、末尾コンマ、長文のための文字列配列を書けます。
- 利用者側の識別子は `sample_` で始めます。ライブラリ側の `string_catalog_` と名前空間を分け、どちらの資産かを名前だけで判別できるようにするためです。例外は型付きラッパーの関数名で、ライブラリの機能を使う組み立てであることを示すため `string_catalog_` を前置します。
- カタログ定義に書くのは、著者、日付、版、文字列の一覧だけです。導出できる名前と、ライブラリが定める仕様を持ち込まないでください。
    - モジュール接頭辞は定義ファイルの名前です。`sample_messages.jsonc` なら `sample_messages` になります。英小文字で始まる snake_case にしてください。
    - 生成物のファイル名はモジュール接頭辞そのもの、文字列 ID の列挙名はそれに `_id` を続けた名前です。
    - ライブラリ側の接頭辞 `string_catalog` は、生成器の定数 `LIBRARY_PREFIX` が補います。
    - `texts` と `notes` に書ける言語は、生成器の定数 `LANGUAGES` が持ちます。ライブラリの `string_catalog_language` を増減した場合は、同じ変更で更新してください。
    - Doxygen が示す置き場所は、定義ファイルの位置から導出します。絶対パスの中で最も近い `prod` または `test` が起点です。
- カタログの名前空間を移す場合は、定義ファイルの名前を変えてください。生成物のファイル名と識別子がすべて追従します。
- 生成物が依存してよいのは、string_catalog の公開ヘッダーと標準ヘッダーだけです。特定の app の型や列挙へ依存させないでください。文字列カタログを共通機能へ移す際に、生成物をそのまま持ち運べるようにするためです。
- 分類値は生値で保持します。定義ファイルにも整数で書き、意味はコメントで示してください。分類値の解釈には `cplat_trace_level` を使用します。値を解釈する側が `<cplat/trace/tracer.h>` を直接インクルードします。
- 文字列 ID の値は、定義の並び順から 1 始まりで生成器が決めます。安定させる必要がある識別子は固定文字列 (`id_text`) であり、これは定義ファイルへ明記します。
- 生成物はカタログ識別オブジェクトと、カタログ指定を省略する簡易関数 (`sample_messages_format` など) を持ちます。ライブラリの API を増やした場合は、対応する簡易関数も同じ変更で追加してください。
- 文字列 ID を追加した場合は、同じ変更で型付きラッパーも追加してください。関数名は、ライブラリ側の接頭辞 `string_catalog_` へ、文字列 ID の定数名を小文字化して続けます。文字列カタログによる組み立てであることを、呼び出し側で名前から判別するためです。区切りのアンダースコアは 1 個とし、2 個続けないでください。C++ が処理系用に予約する識別子になります。
- 文字列 ID の定数名は、ライブラリが公開する名前と衝突しないようにしてください。ラッパーの関数名が `string_catalog_` で始まるため、衝突するとビルドが失敗します。定数名にモジュール接頭辞を含めておけば起こりません。
- 型付きラッパーは `static inline` として `sample_messages.h` に置き、`.c` へ実体を作らないでください。文字列 ID の数だけ公開シンボルが増えることを避けます。関数形式マクロにしないでください。型検査が働かなくなります。
- 生成器を変更した場合は、`bin/test_string_catalog_gen.py` を実行してください。`cd bin && python3 -m unittest test_string_catalog_gen` です。
- カタログをライブラリで保持させないでください。ライブラリが定めるのは、言語、引数種別、書式の構文、結果コードです。
- カタログを参照するライブラリ関数には、カタログ識別オブジェクト (`string_catalog`) を第 1 引数として渡してください。ライブラリへ既定のカタログを持たせないでください。
- `string_catalog` は初期化関数を持たない `const` の値です。メンバーを増やす場合は、静的初期化できる形と、暗黙のパディングが出ないメンバー順を保ってください。
- カタログ指定を省略して呼び出すための簡易関数は、利用側の生成物 `sample_messages.c` に置いてください。ライブラリ側へ戻さないでください。
- ライブラリで `string_catalog_id` という名前を定義しないでください。文字列 ID の列挙は利用者が名付けます。ライブラリは `int` として受け取ります。
- 書式の展開側からカタログを直接参照せず、`prod/include_internal/string_catalog/catalog.h` の関数を経由してください。
- 添字表を変更した場合は、カタログの配列と食い違っていないことを `string_catalog_verify()` で確認してください。
- ニュートラル言語の要素を NULL にしないでください。ほかの言語の要素は、NULL にするとニュートラル言語へ読み替えます。
- 言語別の書式と備考は、言語をキーとした指示付き初期化子で記載してください。リソースを持たない言語は記載を省略します。
- 言語設定はプロセスで 1 つです。組み立て API へ言語引数を追加しないでください。
- 分類値 (`string_catalog_entry::category`) をライブラリで解釈しないでください。意味と有効な範囲は利用者が決めます。範囲の切り詰めはコマンドの `trace_level_of()` が行います。
- 分類値の重大度の意味付け (`cplat_trace_level`) は本 app の規約です。`trace_level_of()` で範囲外の値をフォールバックし、表示名のインデックスとして安全に使用できるようにします。
- 引数種別を追加する場合は、可変長引数の取り出し、文字列表現、公開ヘッダーの対応表を同じ変更で更新してください。既定引数拡張と一致しない `va_arg` の指定を追加しないでください。
- 書式には位置指定とエスケープ以外の構文を追加しないでください。値の文字列表現は引数種別が決めます。
- 引数の上限は 32 個で、インデックスは 0 起点の `{0}` から `{31}` です。書式解析は 10 進数 2 桁までを受け付け、先行ゼロを含むインデックスを認めません。
- 引数の上限を変更する場合は、カタログ 1 件分のサイズと、文字列組み立て 1 回あたりのスタック消費量が上限に比例することを考慮してください。値の配列は実際の引数個数ではなく上限個数分をゼロ初期化します。100 を超える値にする場合は、書式解析の桁数の上限も合わせて拡張してください。

## 局所確認

振る舞いを変更した場合は、影響する局所テストを実行してください。  
app 全体の確認には app 直下の `make test` を使用できます。  
ビルド後は、対象範囲の内容がある `.warn` を確認してください。

カタログの内容を変更した場合は、次のいずれかで整合を確認してください。  
サンプル コマンドは、起動直後に `sample_messages_verify()` を呼び出します。

```bash
./prod/cbin/string-catalog-sample
cd test/src/cmd/sampleMessagesTest && make test
```
