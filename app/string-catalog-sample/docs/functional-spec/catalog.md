# カタログ (catalog) 機能仕様

## 概要

カタログは、文字列 ID ごとに引数スキーマ、分類値、参照名、備考、言語別の書式をまとめた定義の集合です。  
カタログ管理機能は、利用側が用意したカタログを受け取り、文字列 ID から定義を引き、定義の整合を点検します。

## 解決する課題

文字列の文言、引数の型、分類を製品コードへ直接書くと、同じ文字列の情報が複数の場所へ分かれます。  
翻訳の追加や分類の見直しのたびに、離れた場所を同時に変更する必要があります。

文字列の定義をライブラリが抱え込むと、利用側は文字列を追加するたびにライブラリを変更することになります。  
文字列 ID の名前と値も、ライブラリが決めた体系に縛られます。

文字列の分類をライブラリが定めると、用意された区分に合わない運用でも、利用側はその区分へ寄せる必要があります。  
分類の使い道は、出力先の選択、絞り込み、集計など、利用側の運用によって異なります。

カタログは、表計算などの定義から生成する対象です。  
生成した定義と、文字列の組み立てが要求する条件が食い違っても、実際に組み立てるまで気付けません。

文字列の種類が増えると、文字列 ID から定義を引く走査の対象も増えます。

カタログ管理機能は、定義の所有を利用側へ残したまま、受け取り、検索、点検を担います。

## カタログの受け取り

利用側は、文字列 ID ごとの定義を並べた集合と、任意の検索用の表を 1 つのカタログにまとめ、要求ごとに指定します。  
カタログ管理機能はカタログを保持しません。  
そのため、同じプロセスで複数のカタログを扱え、一方への要求が他方の結果を変えることはありません。

定義を複製しないため、指定する領域はそのカタログを使用する間ずっと有効である必要があります。

指定されたカタログが参照できる形でない場合は、要求を行わずに指定が不正であることを通知します。  
参照できない形とは、カタログが無い、定義の集合が無い、要素数が負のいずれかです。

指定の時点では内容を点検しません。  
点検は利用側が明示的に要求します。

カタログを渡す手間を省く仕組みは、利用側が用意します。  
カタログ管理機能は既定のカタログを持ちません。

## 文字列 ID による検索

既定では、定義の全件を走査して文字列 ID の一致を調べます。  
利用側は、文字列 ID を添字として定義の位置を引く表を添えられます。

表を添えた場合は、全件の走査を表による直接の参照へ置き換えます。  
表は文字列 ID が小さい非負整数である場合に使用できます。

表の内容は利用側が用意するため、参照する前に値の範囲を確認します。  
定義の範囲外を示す値を格納した表を与えても、カタログの外を読み出しません。

## 定義の点検

点検は、すべての定義を走査し、次の条件を確認します。

- 書式が構文として正しいこと
- 書式の位置指定の添字が、引数の個数に収まること
- 引数の個数が上限に収まること
- 表を添えた場合、各文字列が表を通して自分自身の定義へ到達すること
- ニュートラル言語の書式と備考が揃っていること

点検は、現在の出力言語だけでなく、すべての言語の資源を対象とします。  
ニュートラル言語以外の資源は欠けていても読み替えの対象になるため、欠けていること自体は条件の違反ではありません。

表からの到達を確認することで、表と定義の集合が食い違った状態と、文字列 ID の重複を検出できます。  
引数の個数と表からの到達に関する違反は言語に依らないため、特定の言語を通知しません。  
分類値は解釈しないため、点検の対象にしません。

カタログは受け取った時点で内容が確定します。  
点検は起動時に一度実行すれば十分であり、文字列を組み立てるたびに実行する必要はありません。

## メタデータの参照

カタログは、書式のほかに次の 3 つを保持します。

| 項目 | 内容 | 言語による違い |
|---|---|---|
| 参照名 | ログの検索キーや障害報告で使う、言語に依らない固定の名前です。 | ありません |
| 分類値 | 利用側が意味を決める整数の補足情報です。 | ありません |
| 備考 | 引数の単位や出力条件など、書式には含めない補足です。 | 現在の出力言語のものを返します |

分類値は、カタログ管理機能が解釈しません。  
重大さの段階、用途、出力先など、値の意味と有効な範囲は利用側が決めます。  
カタログ管理機能は値を検査せず、保持した値をそのまま返します。

分類なしを表す値は 0 です。  
利用側が 0 を意味のある分類値として割り当てることもできますが、その場合は未登録の文字列 ID と区別できません。  
区別が必要な場合は、利用側が先に参照名の有無で存在を確認します。

未登録の文字列 ID では、参照名と備考は存在しないことを通知し、分類値は分類なしを表す値になります。

## 適用範囲外

- 表計算などの定義からカタログの生成物を作る生成器
- 実行時にファイルや外部の資源からカタログを読み込む機構
- 分類値の意味付けと、有効な範囲の定義
- 文字列の出力先への書き出しと、分類値による絞り込み
- 文字列 ID の採番規則と、参照名の決め方
- カタログを省略して呼び出すための、利用側の窓口の形
- 組み立てている最中のカタログの内容の書き換え

## 前提と制約

利用側は、カタログを使用する間ずっと有効な領域でカタログを指定します。

カタログの内容は、文字列を組み立てている間に変更できません。  
カタログ管理機能は同期を持たず、内容が変わらないことを前提に検索します。

利用側は、ニュートラル言語の書式と備考を欠かさずに定義します。  
ほかの言語の資源は欠けていてもかまいません。

利用側は、分類値の意味と有効な範囲を定めます。  
カタログ管理機能は値を検査しないため、範囲外の値を扱う責任は利用側にあります。

表を添える場合、利用側は文字列 ID を小さい非負整数として割り当てます。

## 選択の指針

文字列 ID が連続した小さい非負整数である場合は、表を添えて検索の走査を避けられます。  
文字列 ID が疎である場合や大きい値を含む場合は、表の要素数が増えるため、全件の走査のままにします。

扱うカタログが 1 つだけの場合は、利用側がカタログを補う窓口を用意し、呼び出しからカタログを省きます。  
ライブラリとアプリケーションがそれぞれ文字列を持つ場合は、カタログを分けて、それぞれの窓口を用意します。
