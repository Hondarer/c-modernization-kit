# トレースの条件式フィルターの PoC

## この文書の位置付け

cplat の [文字列カタログの条件式フィルターの設計](../../c-platform/docs/proposals/string-catalog-filter-design.md) (以下、設計資料) を、cplat へ組み込む前に利用側の app で試作します。  
この文書は、試作の範囲、設計資料との差分、判断の理由、進捗を記録します。

試作の本体は `prod/src/cmd/string-catalog-filter-sample/` です。  
cplat と生成器は変更しません。  
試作で形が固まった部分を、設計資料の段階的実装計画に沿って cplat へ移します。

## 試作の目的

- 条件式リストをコンパイルし、ポインターを含まない固定長のメモリ イメージ (フィルター オブジェクト) を得る
- メモリ イメージを先頭ポインターと長さだけでトレース出力側へ引き渡す
- トレースの出力を止めずに、フィルター条件をスレッド セーフに入れ替える
- 適用中の条件を、メモリ イメージからの復元によって一覧表示する
- 条件式の行を追加、編集、削除する

先頭ポインターと長さだけで引き渡すのは、将来、共有メモリに置いたメモリ イメージを 1 対 N のプロセスへ分配するためです。  
メモリ イメージの外に状態を持たなければ、受け取る側のプロセスはイメージだけで同じ判定を再現できます。

## 設計資料から採用するもの

- 条件式の構文 (`key`、`id`、`category`、`arg.<name>`、`arg[<n>]`、判定演算子、`&&`、`||`、`!`、括弧)
- 条件式リストの行の論理和と、不正な行だけを無効にする扱い
- コンパイルと適用の分離。コンパイルはカタログ定義を参照しません。
- 行数と行幅だけで大きさが決まる固定長のフィルター オブジェクト
- 適用時の名前解決と、項目ごとの 3 状態 (常に一致、常に不一致、引数値に依存) の事前計算
- 後置記法の命令列と、短絡評価を条件付きジャンプで表すスタック マシン
- 行の内容のハッシュ値による、未変更行の事前計算の再利用
- 2 面のバッファーと読み書きロックによる差し替え
- デコンパイルと、行単位の追加、編集、削除

自然文での表現 (設計資料の第 3 段階) は、適用中の条件を一覧表示する場面の説明文として取り込みます。  
正規表現 `matches` は、この試作に含めません。

## 設計資料との差分

### 一致した場合の動作

設計資料は、一致した文字列だけを出力し、一致しない文字列は書式展開も行わない方式です。  
この試作では、一致した文字列のトレース レベルを強制出力のレベル (`CPLAT_TRACE_LEVEL_TO_FORCE`) へ引き上げます。  
一致しない文字列は、定義のレベルのまま出力先へ渡し、出力先ごとのしきい値で選別します。

常時の詳細度を出力先のしきい値で決め、調査の対象だけをフィルターで引き上げる運用に合わせるためです。  
条件式リストが空の状態は「何も引き上げない」を意味し、トレースの出力を止めません。

この変更により、一致しない文字列でも書式展開を行います。  
事前計算の効果は、判定のための可変長引数の収集を省略する点に限られます。  
出力先のしきい値を下回る文字列の書式展開を省く最適化は、この試作では扱いません。

### 照合できる引数

照合の対象は、利用者の引数に加えて、生成器が付与する文脈引数 (`{40}` から `{45}`) と app が定義するコンテキスト引数 (`{46}` から `{49}`) のすべてです。  
トレース種別の引数配列は常に 50 個を確保し、名前を持つ引数はすべて `arg.<name>` で参照できます。  
条件式に現れた引数だけを照合し、現れない引数は判定の計算量に影響しません。

### cplat が意識しない追加コンテキスト

試作のカタログは、app が定義するコンテキスト引数としてラウンド トリップ ID (`{46}` の `sequence_number`) を持ちます。  
`samplecatalog` の巡回連番と同じ方式で、`catalog_settings.jsonc` の `context` 節に取得式を記述し、出力要求ごとに 1 から 99 までを巡回します。

cplat はこの引数の意味を知りません。  
条件式フィルターは引数名をカタログの引数定義から解決するため、`arg.sequence_number` や `arg[46]` を cplat の文脈引数と同じ規則で照合できます。  
フィルター側に app 固有の知識を持ち込まずに追加コンテキストを評価できることを、この引数で確かめます。

試作の出力マクロは生成物の型付きラッパーを経由しないため、取得式をマクロの中でも呼び出します。  
app が定義するコンテキスト引数を増減した場合は、`catalog_settings.jsonc` と出力マクロを同じ変更で更新します。  
生成器へ差し込み口を追加する段階では、生成物の `_with_source` が取得式を展開するため、この二重管理はなくなります。

### フィルター オブジェクトの検証

設計資料の検証項目に加えて、有効な行の内容から算出したハッシュ値をヘッダーへ記録し、適用の時点で照合します。  
共有メモリから複製する途中で書き換えが起きた場合に、ちぎれたイメージを検出するためです。

### 判定とトレース出力の結び付け

cplat の内部関数 `string_catalog_collect_arguments()` は公開されていないため、試作では同等の引数収集を app 側に持ちます。  
可変長引数は、判定用の収集に `va_copy` した複製を使い、書式展開には元の引数リストを `cplat_string_catalog_vformat()` へ渡します。  
cplat へ組み込む段階では、設計資料のとおり収集結果を判定と展開で共有し、`va_copy` を不要にします。

生成物の型付きラッパーは、生成物の `<module>_write()` を直接呼び出します。  
試作では生成器を変更しないため、呼び出し位置を付与する関数形式マクロを app 側に用意し、フィルターを通す出力関数へ渡します。  
このマクロは引数の型を検査しません。  
型検査は、生成器へ差し込み口を追加する段階で、型付きラッパーによって回復します。

### 自然文での表現

設計資料の `cplat_string_catalog_filter_slot_describe_line` に相当する `sample_filter_slot_describe_line()` を、フィルター スロットに持たせます。  
文字列キーの比較は項目の `brief` と `id`、引数の比較は引数の名前と説明、分類値の比較は値そのもので表します。  
文型は日本語とニュートラル言語 (英語) を持ち、`cplat_string_catalog_get_language()` が日本語を返す場合だけ日本語を使います。

設計資料との差分は次の 3 点です。

- 行が 1 つの項目に限定されるかどうかは、適用時の事前計算結果から判定します。行ごとの判定結果が「常に不一致」ではない項目が 1 つだけ存在する場合に、その項目へ限定されているとみなします。`key ==` を書いた行に限らず、`arg.buffer == null` のように引数の有無で項目が 1 つに絞られる行も対象になります。
- 複数の項目が対象の行でも、引数を持つすべての項目で引数の説明が一致する場合は、その説明を使います。設計資料では引数の名前だけを使います。文脈引数やラウンド トリップ ID のように、全項目が同じ説明を持つ引数を説明付きで表すためです。
- 文型は文字列カタログの書式展開を再利用せず、主語、演算子の前後の語、値を並べる表で持ちます。言語による語順の違いは、演算子の前後の語で吸収できる範囲にとどめます。

カタログのメタ情報 (`brief` と引数の説明) は言語別に持たないため、どちらの文型でもカタログの記述をそのまま埋め込みます。  
文の途中へ埋め込むため、文末の句点は除きます。

名前を解決できずに無効とした行は、メタ情報と結び付けられないため、説明文を作りません。

### デコンパイルの括弧

設計資料は、括弧を演算子の優先順位から必要な位置にだけ付与します。  
この試作では、`!` の対象が判定要素の場合にも括弧を付けます。  
`!key == 1` は構文上 `!(key == 1)` ですが、C の読み方では `(!key) == 1` と誤読されるためです。  
括弧は命令を生成しないため、復元した条件式を再コンパイルした結果は変わりません。

### 名前解決テーブル

設計資料の第 2 段階で生成器が出力する `<module>_key_names()` の代わりに、試作では app 側に表を手書きします。  
表の名前は列挙定数を文字列化して作るため、綴りの誤りはコンパイル エラーになります。  
件数とカタログの項目数の一致は、起動時に確認します。

## フィルター オブジェクトの形式

すべての値は固定幅の整数型で表し、アラインメントを 8 バイトにそろえます。  
呼び出し側の領域はアラインメントを保証しないため、読み書きは `memcpy` を介して行います。

| 要素 | 大きさ |
|---|---|
| ヘッダー | 64 バイト |
| 行レコード | 行数の上限 × 行レコード長 |

行レコード長は、行幅 `M` から次のとおり求めます。

```text
行レコード長 = 16 + 8 × M (命令領域) + 8 × M (定数領域)
```

1 つの命令は、条件式の文字列の中で 1 文字以上を消費します。  
判定要素は 5 文字以上、`!` は 1 文字で 1 命令、`&&` と `||` は 2 文字で 2 命令 (ジャンプと結合) です。  
そのため、命令数は行幅を超えません。

定数は、8 バイトの見出しと、8 バイト単位にそろえた値で構成します。  
1 つの定数は、区切りを含めて 2 文字以上を消費し、1 文字あたりの消費は 8 バイト以下です。

## 実行中の差し替え

フィルター スロットは、適用する内容を 2 面のバッファーで持ちます。  
適用は使用していない面へ複製と事前計算を行い、排他モードのロックの下で参照する面を切り替えます。  
判定は共有モードのロックの下で行い、書式展開と出力はロックの外で行います。

適用の関数が戻った時点で、引き渡したメモリ イメージは参照されません。  
呼び出し側は、戻った直後にその領域を再利用または解放できます。
