# string-catalog-filter-sample コマンド

トレースの条件式フィルターの試作を対話的に確認します。  
ワーカー スレッドが 7 種類のトレースを出し続ける間に、条件式を編集して適用し、スレッド セーフな差し替えと表示の変化を確認できます。

設計の背景、設計資料との差分、進捗は [トレースの条件式フィルターの PoC](../../../../docs/trace-filter-poc.md) を参照してください。  
本 README は、このコマンドの構成と操作方法だけを扱います。

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `sample_filter.h` / `sample_filter_compile.c` | 条件式のコンパイル、行単位の編集、デコンパイル (カタログ定義を参照しない層) |
| `sample_filter_image.h` / `sample_filter_image.c` | フィルター オブジェクトの内部形式 |
| `sample_filter_slot.c` | フィルター スロット (名前解決、事前計算、判定、2 面の差し替え) |
| `sample_filter_describe.c` | 条件式を、カタログのメタ情報を用いた自然文で表現する説明文 |
| `sample_filter_output.h` / `sample_filter_output.c` | フィルターを通してトレースを出力する入口。`sample_filter_output(key, ...)` マクロを提供 |
| `sample_worker_trace.jsonc` / `gen/sample_worker_trace.h` | ワーカーが出力するトレースのカタログ定義と生成物 |
| `sample_worker_trace_key_names.h` / `.c` | 文字列キーの名前解決テーブル (手動定義) |
| `string-catalog-filter-sample.c` | 本コマンドの対話ループとワーカー スレッドの実装 |

## コマンド一覧

| コマンド | 内容 |
|---|---|
| `help` | コマンドの一覧を表示します |
| `usage` | 条件式の例を表示します。例は `add` や `edit` へそのまま指定できます。分類値に指定できるレベルと列挙値、条件式から参照できるコンテキスト引数 (`{40}` 以降の番号、名前、型、説明) の一覧もあわせて表示します |
| `list` | 適用中の条件式を、カタログのメタ情報を用いた説明文とともに表示します |
| `draft` | 編集中の条件式を、`list` と同じく説明文とともに表示します |
| `add <条件式>` | 編集中イメージの末尾へ条件式を追加します |
| `insert <n> <条件式>` | 編集中イメージの `n` 行目へ条件式を挿入します |
| `edit <n> [<条件式>]` | 編集中イメージの `n` 行目を置き換えます。条件式を省略すると、次の入力欄に `edit <n> <現在の条件式>` を入れて呼び出します。編集して確定すると置き換わります |
| `delete <n>` | 編集中イメージの `n` 行目を削除します |
| `clear` | 編集中イメージを空にします |
| `revert` | 適用中の条件を編集中イメージへ複製します |
| `image` | 編集中イメージのアドレス、ヘッダー情報、先頭 64 バイトのダンプを表示します |
| `apply` | 編集中イメージを適用します |
| `state` | 文字列キーごとの判定状態 (常に不一致 / 常に一致 / 引数値に依存) を表示します |
| `display [レベル]` | 表示のしきい値を取得または設定します |
| `language [ja\|en\|neutral]` | 出力言語を取得または設定します。トレースの文字列と、`list` の説明文の文型が切り替わります |
| `emit` | 7 種類のトレースを 1 回ずつ出力します (決定的な確認用) |
| `start [ワーカー数] [間隔 ms]` | ワーカー スレッドを起動します (既定 2 個、500 ミリ秒間隔) |
| `stop` | ワーカー スレッドを停止します |
| `quit` / `exit` | 終了します |

行番号は `1` 起点で表示、入力します。  
入力したコマンドは、空行を 1 行置いてから `filter-sample> ` を前置して出力領域へ書き戻します。  
直前のコマンドの応答のあとに表示がなければ、応答のあとの空行で区切られているため、書き戻しの前の空行は省きます。  
コマンドの間の空行は常に 1 行です。  
固定プロンプトから消えた入力を、出力の流れの中で追えるようにするためです。

空行、入力の書き戻し、コマンドの応答、応答のあとの空行までは、ワーカーのトレースを挟まずに続けて表示します。  
その間にワーカーが出したトレースは表示を保留し、応答のあとの空行に続けてまとめて表示します。  
ワーカーのスレッドそのものは待機させません。  
`stop` がワーカーの終了を待つ間に、ワーカーが表示の再開を待つと、互いに待ち合って進まなくなるためです。  
保留できる行数を超えた分は破棄し、破棄した件数を表示します。

標準入力または標準出力が端末でない場合、プロンプトと入力は同じ行に並びます。  
この場合は、プロンプトの前の空行から応答のあとの空行までを、続けて表示する区間とします。

## 条件式の例

`add` や `edit` に指定できる条件式の例です。  
同じ例を、コマンドの `usage` でも表示できます。  
いずれも、このコマンドで `add` と `apply` を実行し、無効な行にならないことを確認しています。  
構文と比較規則の詳細は [文字列カタログの条件式フィルターの設計](../../../../../c-platform/docs/proposals/string-catalog-filter-design.md) の「条件式の仕様」を参照してください。

条件式リストは行の論理和です。  
いずれかの行に一致したトレースは強制出力のレベルへ引き上がり、一致しないトレースは定義のレベルのまま表示のしきい値で選別されます。

### 項目の情報で選ぶ

| 条件式 | 引き上げる対象 |
|---|---|
| `category <= 2` | レベルが WARNING 以上に重大なトレース (数値で指定) |
| `category <= WARNING` | 同上 (レベル名で指定) |
| `key == SAMPLE_WORKER_TRACE_KEY_JOB_PROGRESS` | ジョブの進捗 |
| `key in [SAMPLE_WORKER_TRACE_KEY_JOB_RECEIVED, SAMPLE_WORKER_TRACE_KEY_JOB_FAILED]` | ジョブの受け付けと失敗 |
| `id ends_with "0005"` | ID が `SAMPLE_WORKER_TRACE_ID_0005` のトレース (ジョブの失敗) |

分類値にはレベルの名前と列挙値のどちらでも書けます。  
対応は CRITICAL = 0、ERROR = 1、WARNING = 2、INFO = 3、VERBOSE = 4、DEBUG = 5、NONE = 6 です。

これらの行は引数の値を参照しないため、適用の時点で項目ごとに一致が確定します。  
`state` では「常に一致」または「常に不一致」と表示され、出力時に可変長引数を収集しません。

### 利用者の引数で選ぶ

| 条件式 | 引き上げる対象 |
|---|---|
| `arg.worker_index == 1` | ワーカー 1 のトレース |
| `arg.job_name starts_with "import"` | ジョブ名が `import` で始まるジョブの受け付け |
| `arg.job_name contains_i "EXP"` | ジョブ名に `exp` を含むジョブの受け付け (ASCII の大文字と小文字を区別しない) |
| `arg.priority between -3 and 3` | 優先度が -3 以上 3 以下のジョブの受け付け |
| `arg.ratio >= 0.9` | 進捗の割合が 0.9 以上のジョブの進捗 |
| `arg.buffer == null` | 確保に失敗したバッファーの確保 |
| `arg.byte_count > 200` | 200 バイトを超えるバッファーの確保 |
| `arg.error_code == -2` | エラー コードが -2 のジョブの失敗 |
| `arg.command == 's'` | コマンドの文字が `s` の制御コマンドの受信 |
| `arg.status == 0x1F` | 状態フラグが 0x1F の制御コマンドの受信 |
| `arg.delta < 0` | 差分が負の制御コマンドの受信 |

引数を持たない項目では、その引数を参照する比較は偽になります。  
たとえば `arg.priority between -3 and 3` は、ジョブの受け付け以外には一致しません。

### 呼び出し位置と実行コンテキストで選ぶ

| 条件式 | 引き上げる対象 |
|---|---|
| `arg.function_name == "emit_job_failed"` | 関数 `emit_job_failed` から出力したトレース |
| `arg.source_file_name ends_with ".c"` | 拡張子が `.c` のソースから出力したトレース |
| `arg[42] > 300` | 300 行目より後ろの呼び出し位置から出力したトレース (`{42}` は `source_line`) |
| `arg.sequence_number between 90 and 99` | ラウンド トリップ ID が 90 から 99 のトレース |
| `arg[46] == 1` | ラウンド トリップ ID が 1 のトレース |

`{40}` から `{45}` は cplat の生成器が付与する文脈引数、`{46}` の `sequence_number` はこの app が定義するコンテキスト引数です。  
どちらも引数名またはインデックスで、利用者の引数と同じように照合できます。  
コンテキスト引数の一覧は `usage` で確認できます。  
一覧はカタログの定義から作るため、`catalog_settings.jsonc` で引数を増減すると表示も追従します。

### 組み合わせる

| 条件式 | 引き上げる対象 |
|---|---|
| `key == SAMPLE_WORKER_TRACE_KEY_JOB_FAILED && arg.error_code != -2` | エラー コードが -2 以外のジョブの失敗 |
| `arg.worker_index == 0 && !(arg.job_name starts_with "export")` | ワーカー 0 のトレースのうち、ジョブ名が `export` で始まるものを除いたもの |
| `(arg.priority < 0 \|\| arg.ratio >= 0.9) && has(arg.job_id)` | ジョブ番号を持つトレースのうち、優先度が負、または進捗の割合が 0.9 以上のもの |

`!`、`&&`、`||` の順に強く結合します。  
除外の条件は、同じ行の中で `!` を使って記述します。

### 無効になる例

| 条件式 | 結果 |
|---|---|
| `arg.no_such == 1` | どの項目にもない引数名のため、`apply` で無効な行になります (未解決の引数名) |
| `category starts_with "x"` | 分類値は整数のため、`add` の時点で拒否されます (型不一致) |

無効な行は、その行だけが適用されず、他の行は適用されます。  
`list` では、無効な行に `[無効]` が付きます。

## 説明文

`list` と `draft` は、各行の下に、カタログのメタ情報を用いた説明文を `→` に続けて表示します。  
`list` は適用中の条件、`draft` は編集中の条件が対象です。  
`draft` は、編集中イメージを下見用のフィルター スロットへ適用してから表示します。  
下見用のスロットはトレース出力に結び付けないため、適用中の条件は変わりません。  
`apply` の前に、名前を解決できない行を `[無効]` として確認できます。  
文字列キーは項目の `brief` と ID、引数は引数の名前と説明で表します。  
分類値は、このコマンドがトレース レベルとして扱うため、条件を満たすレベルの名前で表します (例: `category <= 2` は「レベルが CRITICAL、ERROR、WARNING のいずれか」)。  
満たさないレベルのほうが少ない場合は「レベルが VERBOSE 以外」のように表します。

条件式の分類値は、数値とレベル名のどちらでも書けます (`category <= 2` と `category <= WARNING` は同じ条件です)。  
`add`、`insert`、`edit` は、CRITICAL から NONE 以外のレベル名、0 から 6 以外の数値、整数でない数値を拒否し、編集中の条件を変えません。

```text
filter-sample> list
   1: key == SAMPLE_WORKER_TRACE_KEY_JOB_FAILED && arg.error_code != -2
      → 「ジョブの失敗」(SAMPLE_WORKER_TRACE_ID_0005) かつ 引数 error_code (errno または Win32 のエラー コード) が -2 ではない
   2: arg.sequence_number between 90 and 99
      → 引数 sequence_number (出力ごとに 1 から順に増加し、上限に達すると 1 へ戻るラウンド トリップ ID) が 90 以上 99 以下
   3: [無効] key == NO_SUCH_KEY
```

行が 1 つの項目に限定される場合は、その項目の引数の説明を使います。  
複数の項目が対象の場合は、引数を持つすべての項目で説明が一致するときに限り、説明を添えます。  
無効な行は、名前を解決できていないため説明文を表示しません。

説明文の文型は、出力言語が日本語 (`language ja`) の場合は日本語、それ以外はニュートラル言語 (英語) です。  
カタログのメタ情報は言語別に持たないため、どちらの文型でもカタログの記述がそのまま入ります。

## 表示のしきい値とフックの仕組み

出力先のトレーサーは、標準エラー出力や OS トレースを含めて既定でいずれも無効です。  
代わりにフックを登録し、フックの内部で表示のしきい値と比較して、通過した文字列だけを端末へ表示します。

条件式に一致したトレースはレベルが強制出力のレベルへ引き上がり、表示のしきい値によらず常に表示されます。  
この場合は `[FORCE:<元のレベル>]` の形式で表示し、絞り込みの結果であることを区別します。

## コンテキスト引数 sequence_number

生成器が付与する文脈引数に加えて照合できる、本 app 固有のコンテキスト引数は [トレースの条件式フィルターの PoC](../../../../docs/trace-filter-poc.md) の「照合できる引数」を参照してください。  
`sample_worker_trace` はコンテキスト引数の 1 つとして `sequence_number` (1 から 99 を巡回するラウンド トリップ ID) を割り当てており、`arg.sequence_number` で参照できます。  
取得と付与は `sample_filter_output` マクロが自動で行うため、コマンド側の出力呼び出しを変更する必要はありません。  
この連番は組み立てた文字列の先頭に `#<連番> ` として現れます。

## 使用方法

```bash
./prod/cbin/string-catalog-filter-sample
```

起動直後に `sample_worker_trace` カタログと名前解決テーブルの整合を検証し、不正があれば終了コード 1 で終了します。

### 操作例

次の手順で、条件式の追加から適用、実行中の差し替えまでの流れを確認できます。

```text
filter-sample> add arg.priority < 0
行 1 を追加しました。

filter-sample> image
先頭アドレス: 0x...
バイト数: 131648
行数の上限: 32
行幅: 256
格納行数: 1
形式版: 1
内容のハッシュ値: 0x...
このアドレスとバイト数を、トレース出力側へ先頭ポインターと長さで引き渡します。

filter-sample> apply
適用しました。

filter-sample> list
   1: arg.priority < 0

filter-sample> start
ワーカー 2 個を間隔 500 ms で起動しました。
[FORCE:DEBUG] #12 ワーカー 0 がジョブ 1 (export-0、優先度=-9) を受け付けました。

filter-sample> edit 1 arg.priority > 5
行 1 を置き換えました。

filter-sample> apply
適用しました。
[FORCE:DEBUG] #45 ワーカー 1 がジョブ 1016 (import-1、優先度=6) を受け付けました。

filter-sample> edit 1 arg.sequence_number between 90 and 99
行 1 を置き換えました。

filter-sample> apply
適用しました。
[FORCE:WARNING] #97 ジョブ 1017 が失敗しました。エラー コード=5 (0x00000005)
```

`add` で条件式を編集中イメージへ追加し、`image` で引き渡し対象のメモリ イメージを確認し、`apply` で適用します。  
`list` で適用中の条件式を確認したあと `start` でワーカーを起動すると、条件式に一致したトレースだけが強制出力の表示で流れます。  
稼働中のまま `edit` と `apply` を繰り返すと、出力が止まらずに一致する行だけが変わることを確認できます。  
最後の `arg.sequence_number between 90 and 99` は、cplat が意識しない app 固有のコンテキスト引数を条件式から参照する例です。

出力は UTF-8 です。Windows のコンソールで文字化けする場合は、あらかじめ `chcp 65001` を実行してください。
