# 同期 IPC (ipc) 機能仕様

## 概要

同期 IPC 機能は、同一ホスト上で動作する任意のプロセスへ同期的に処理要求を送り、応答を受け取るための汎用的なローカル プロセス間通信手段を提供します。

利用側は、1 回の要求ごとに接続して切断する単発接続と、1 本の接続を保持して複数の要求を直列に送受信する持続接続を用途に応じて選択できます。  
本機能はプロセスとりまとめ固有の概念を含まず、任意のメソッド識別子と任意のバイト列ペイロードをやり取りする汎用基盤として独立して機能します。

## 解決する課題

同一ホスト上の複数プロセス間で処理の依頼と結果の受け取りを行う場合、OS ごとに異なるローカル通信機構、電文の境界判定、タイムアウト制御、残骸エンドポイントの清掃、および多数の同時接続に対する資源保護を利用側が個別に実装する必要があります。

また、単純な 1 接続 1 スレッド構成で持続接続を受け入れると、待機中のクライアントがスレッドを占有し、他のクライアントからの要求が処理できなくなります。

同期 IPC 機能は、固定長の電文ヘッダーと不透明なバイト列ペイロードによる要求応答モデル、単発接続と持続接続の両立、待機中接続が処理スレッドを占有しないサーバー接続管理、および Linux と Windows で共通のエンドポイント概念を提供します。

## 単発接続と持続接続

利用側は、1 回の通信だけで完結する管理操作には単発接続を使用し、高頻度に連続呼び出しを行う用途には持続接続を使用できます。  
両方式とも同一の電文形式と同一のサーバー エンドポイントを使用するため、サーバー側は接続方式を意識せずにハンドラーを登録できます。

持続接続がサーバー側のアイドル切断期限や相手プロセス終了によって切断された場合、次の要求呼び出しは切断エラーを返します。  
再接続するか処理を中断するかの判断は、常に利用側が行います。

## サーバーの同時接続管理と資源保護

サーバーは、接続の待ち受けと待機中接続の読み取り監視を固定ワーカー スレッド群から分離して処理します。  
読み取り可能となった接続だけをワーカーへ引き渡し、1 要求の応答送信が完了した持続接続は再び監視集合へ戻します。

この構造により、処理スレッド数より多くの持続接続がアイドル状態で滞留していても、新規の単発接続や他の持続接続からの要求がブロックされません。  
また、最大同時接続数とアイドル切断期限により、クライアントが切断を忘れた場合でもファイル記述子やハンドルの枯渇を防ぎます。

## エンドポイント空間とアクセス権

エンドポイントは名前空間、インスタンス名、宛先名の組で論理的に識別します。

- **同一ユーザー空間**: ログイン中の同一ユーザーが所有する一時領域へ配置し、Linux では所有者のみがアクセスできる権限 (ディレクトリ `0700`、ソケット `0600`) を設定します。
- **隔離ディレクトリ空間**: 利用側が指定したベース ディレクトリ直下へ配置します。自動テストや複数環境の並存時に互いに干渉しない隔離用途に使用します。
- **共通サービス空間**: 将来の daemon または Windows Service 向けの予約空間であり、現時点では未対応エラーを返却します。

## 適用範囲外

- ネットワーク越しの別ホスト間通信 (TCP / UDP)
- サーバーからクライアントへの非同期プッシュ通知、ブロードキャスト、および 1 接続上での要求パイプライン多重化
- 共通サービス空間における異ユーザー間の権限制御および実機動作保証
- 通信ペイロードの暗号化、圧縮、およびスキーマ定義
- 切断時のクライアント側自動再接続および要求の自動再試行

## 前提と制約

- 通信対象は同一ホスト上で動作するプロセスに限ります。
- 持続接続ハンドルの破棄操作と、同じハンドルに対する要求呼び出しを別スレッドから同時に行ってはなりません。
- サーバー側のメソッド ハンドラーは複数の処理スレッドから同時に呼び出されるため、ハンドラー内で共有する状態は呼び出し側で同期する必要があります。
- Unix ドメイン ソケット使用時は OS のソケット パス長制限に従うため、利用側は解決後パス長が 107 バイト以内に収まるベース ディレクトリおよび識別子を指定する必要があります。
- Windows で Unix ドメイン ソケットを使用する場合は、ネイティブ Unix ドメイン ソケットに対応する Windows 10 (1803 以降) または Windows 11 が必要です。

## 選択の指針

- 1 回限りの制御操作や低頻度の状態照会では、接続状態の管理が不要な単発接続を選択します。
- 同一プロセスに対して短時間に多数回の同期呼び出しを行う場合は、接続確立コストを省ける持続接続を選択します。
- Windows 環境では既定の Unix ドメイン ソケットを優先し、名前付きパイプとの性能比較または互換検証を行う場合に限り名前付きパイプを明示選択します。
