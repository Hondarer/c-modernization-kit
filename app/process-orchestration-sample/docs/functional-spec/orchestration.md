# プロセスとりまとめ (orchestration) 機能仕様

## 概要

プロセスとりまとめ機能は、1 つの親プロセスが 3 つの子プロセス (子 1〜3) を起動・監視・制御し、親プロセスでも子プロセスでもない第三者プロセスから親への制御指示と稼働中の子への直接指示を行える仕組みを提供します。

親プロセスは子プロセスのライフサイクル状態を一元管理します。  
一方で、子プロセスへの業務処理に相当するエコー バック要求は、親プロセスを経由せず第三者プロセスから対象の子プロセスへ直接送信します。

## 解決する課題

複数のワーカー子プロセスを統括する構成では、起動直後に子プロセスが要求を受け付けられる状態になったことの確認、予期せぬ終了の検知と状態保持、終了要求時のグレースフル停止と応答しない子の強制終了、および親を経由しない直接通信の役割分担を整理する必要があります。

また、子プロセスが異常終了した際に親が自動で再起動してしまうと、外部の監視・制御側が異常終了の事実と終了コードを確実に把握できない場合があります。

プロセスとりまとめ機能は、親起動時の子 1〜3 の一括起動、異常終了時の非自動再起動と異常終了状態の保持、外部指示による子の起動・停止・状態取得・親の終了、および子への直接エコー バックを一貫した状態モデルで提供します。

## 子プロセスのライフサイクル状態

子プロセスは次の 5 つの状態を持ちます。

- **停止 (`STOPPED`)**: 未起動、または「子の終了」指示による意図的な停止が完了した状態です。PID は 0 です。
- **起動中 (`STARTING`)**: 親が子プロセスを起動し、子の直接通信エンドポイントが応答可能になるのを待っている状態です。
- **稼働中 (`RUNNING`)**: 子プロセスが起動し、直接エコー バックを受け付けられる状態です。有効な PID を持ちます。
- **停止中 (`STOPPING`)**: 親が子へ停止指示を送り、終了と回収を待っている状態です。
- **異常終了 (`CRASHED`)**: 意図的な停止操作以外で子が予期せず終了した状態です。親は自動再起動を行わず、PID を 0 とし、取得した終了コードを保持します。

異常終了した子プロセスを復帰させるには、第三者プロセスから親プロセスへ「子の起動」を明示的に指示します。  
復帰に成功すると、新しい PID が割り当てられ、累計起動回数が 1 加算されて稼働状態へ遷移します。

## 親経由の制御と子への直接指示の分離

親プロセスのエンドポイントは、親終了・子起動・子終了・子状態取得の 4 つの管理操作だけを受け付けます。  
子 1〜3 の各エンドポイントは、親を経由しない直接エコー バック、親からの起動完了確認、および親からのグレースフル停止要求を受け付けます。

停止状態または異常終了状態の子に対して直接エコー バックを送信した場合は、対象の子が稼働していないため接続エラーまたは応答エラーとなります。

## 適用範囲外

- 4 つ以上の子プロセス、または動的な子数の増減
- 子プロセスの異常終了時における親プロセスによる自動再起動や指数バックオフ制御
- 親プロセス自身の異常終了からの自動復旧
- 異なるホストにまたがるプロセス制御
- OS のサービス管理機構 (systemd や Windows Service Control Manager) への登録と連携

## 前提と制約

- 親プロセスと子プロセスは同一のエンドポイント空間設定 (空間スコープ、インスタンス名、バックエンド、隔離ディレクトリ) で動作する必要があります。
- 同一のエンドポイント空間で複数の親プロセスを同時に起動することはできません。2 つ目以降の親プロセスは起動時にビジー エラーで終了します。
- 親プロセスは自身と同一の配置先から子プロセスの実行体を起動できる環境を前提とします。
