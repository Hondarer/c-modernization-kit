# CI エラーと警告の確認と修正

## 対象

この手順は、CI の失敗と警告アーティファクトを同じ実行単位で確認する場合に使用します。  
ビルドまたはテストが失敗している場合は、失敗ログを先に調査し、修正後に警告の確認へ進みます。

## マトリクス ジョブの確認

同じ CI 実行に含まれる Linux、Windows、文書生成などの全ジョブについて、終了状態と警告アーティファクトの有無を一覧化します。  
一つの OS で成功していても、別の OS におけるコンパイル、リンク、実行結果を確認済みとはみなしません。  
手元で実行できない OS は、ログに記録されたコマンド、エラー、対象処理のプラットフォーム分岐を照合します。

## 確認対象

- `docs-warns.zip`
- `linux-ol8-warns.zip`
- `linux-ol9-warns.zip`
- `linux-ol10-warns.zip`
- `windows-warns.zip`

対象の CI 実行からアーティファクトを取得し、警告を発生元のファイルとオプションごとに分類します。

## 修正手順

1. 警告の発生箇所とビルド条件を確認します。
2. 同種の既存実装と正本規範を確認します。
3. 修正範囲と、必要な局所ビルドまたはテストをユーザーへ示します。
4. 警告の原因を修正します。
5. 最小範囲のビルドまたはテストを再実行します。
6. 内容がある `.warn` ファイルが残っていないことを確認します。
7. 対象とした全ジョブの失敗と警告アーティファクトについて、修正結果または未確認の理由を対応付けます。

手順 3 は進捗報告であり、すでに依頼された修正を確認待ちで中断する条件ではありません。  
変更起因の失敗は修正し、許可された局所検証を再実行します。  
既存の無関係な警告や環境不足は対象の修正結果と分けて報告し、全体テストなどの追加確認が必要な操作はワークスペースの指示に従います。

`.warn` ファイルや取得したログは直接修正しません。

## -Wpadded

構造体のパディング警告は、メンバー順、ABI、公開構造体かどうかを確認して判断します。  
公開 ABI を変更する可能性があるため、警告抑制のみを目的にメンバーを並べ替えません。  
判断基準は [コーディング規範](../../general/docs/coding-guideline.md) の構造体パディングに関する節を参照してください。
