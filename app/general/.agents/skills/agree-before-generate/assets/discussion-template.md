## 作業 WBS と進捗管理

この検討用 Markdown が管理する作業 WBS です。検討用 Markdown のための情報収集と質問の実施、検討用 Markdown の承認の受付 (第 1 ゲート)、最終決定事項 (最終仕様) を記載した `対象となる事柄-design.md` (または `案件ディレクトリ/design.md`) の作成、最終仕様の承認の受付 (第 2 ゲート)、および承認された最終仕様に従って作業を完遂するまでの詳細な手順をチェックリスト形式で記載します。  
具体的な作業対象 (設計書、ソース コード、設定ファイルなど) を明記し、Q&A のターンごとに必要に応じて見直します。各ゲートの承認および作業の進行に従ってチェックを更新します。

- [ ] 1. 検討用 Markdown のための情報収集と質問の実施
    - [ ] 1.1. 前提条件と要求事項の調査
    - [ ] 1.2. 課題・論点の抽出と明確化のための確認項目 ([Q-001](#q-001-質問の短い題名)) の作成
    - [ ] 1.3. Q&A ターンごとのユーザー回答の受付と記録 (JST 日時、Git ユーザー名または発言者)
    - [ ] 1.4. 回答に基づく前提・制約の検証と WBS の見直し
- [ ] 2. 検討用 Markdown の承認の受付 (第 1 ゲート)
    - [ ] 2.1. 全論点に対する未解決事項の解消確認
    - [ ] 2.2. 対話セッションにおける検討用 Markdown の承認の受付 (方針・前提条件の合意)
- [ ] 3. 最終決定事項 (最終仕様) の作成と承認の受付
    - [ ] 3.1. `対象となる事柄-design.md` (または `案件ディレクトリ/design.md`) の作成
    - [ ] 3.2. 最終仕様における受入条件と整合性の確認
    - [ ] 3.3. 対話セッションにおける最終仕様 (design.md) の承認の受付 (第 2 ゲート: 作業着手の合意)
- [ ] 4. 承認された最終仕様に従った作業の完遂
    - [ ] 4.1. 対象ファイル A (path/to/fileA) の作成・更新
    - [ ] 4.2. 対象ファイル B (path/to/fileB) の作成・更新
    - [ ] 4.3. 局所テストおよび機械的検証 (text_style_jp 等) の実施
    - [ ] 4.4. 受入条件への適合確認 (全完確認)
    - [ ] 4.5. 未対応残渣がある場合の残課題記録 (`backlog.md` の作成)
    - [ ] 4.6. 作業完了報告
