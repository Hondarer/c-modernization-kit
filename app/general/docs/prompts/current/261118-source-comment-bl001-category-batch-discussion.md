### 一次資料から確認した事実

Microsoft Learn の各ページを 2026-11-18 に確認しました。

- [BCryptCloseAlgorithmProvider](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptclosealgorithmprovider)、[BCryptDestroyKey](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptdestroykey)、[BCryptDestroyHash](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptdestroyhash) が失敗の戻り値として挙げるのは、ハンドルが無効な場合の `STATUS_INVALID_HANDLE` だけです。失敗後のハンドルの状態は記載がありません。
- [setvbuf](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/setvbuf) は、ストリームが NULL の場合と、モードまたはサイズが不正な場合に失敗し、-1 を返します。対象は「開いた後に入出力をしていないストリーム」とされています。
- [_close](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/close) が挙げる失敗は、ファイル記述子が不正な場合の `EBADF` だけです。
- [_dup2](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/dup-dup2) は、複製先のファイル記述子が開いている場合、それを閉じてから複製します。失敗は `EBADF` と `EMFILE` です。
- [SetStdHandle](https://learn.microsoft.com/en-us/windows/console/setstdhandle) は失敗時に 0 を返します。失敗後の状態は記載がありません。
- [SetServiceStatus](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-setservicestatus) は失敗時に 0 を返します。エラーとして `ERROR_INVALID_DATA` と `ERROR_INVALID_HANDLE` を挙げています。`SERVICE_STOPPED` の通知は 1 回だけ行い、その後に再び呼ぶとプロセスが異常終了する場合があるとしています。
- [ChangeServiceConfig2](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-changeserviceconfig2a) は失敗時に 0 を返します。

### ソースから確認した事実

- `cplat_elevated_process_attach_output_pipes()` の公開ヘッダーは、「Win32 の標準ハンドルと CRT の stdout / stderr をパイプへ付け替える」「stdout はバッファーなしに設定する」と記載しています。043 と 048 は、この記載の成立にかかわる呼び出しです。
- 同じ関数は、プログラム開始直後に 1 度だけ呼ぶ契約です。呼び出し元の `eventlog-register.c` は、失敗時に `EXIT_FAILURE` で終了します。
- 同じ関数は、stdout の付け替えに成功した後で stderr の付け替えに失敗した場合も `CPLAT_ERR_UNKNOWN` を返します。失敗した時点の標準ストリームの状態は、公開ヘッダーに記載がありません。
- `struct_meta_sample.c` の `main` には、ヘルプ出力の後に `fflush(stdout) != 0 || ferror(stdout) != 0` で失敗を検査する既存の書き方があります。ストリームへの書き込みを 1 回ずつ検査せず、区切りの位置でまとめて検査する方法です。
- 既存のテストとして、`benchIoFailureTest`、`structMetaSampleIoTest`、`traceFileIntegrationTest`、`elevatedProcessTest`、`service-sampleTest`、`sampleMessagesTest`、`sampleFilterTest`、`override-sampleTest` のディレクトリがあります。

/* 案 A: 伝達 */
if (setvbuf(stdout, NULL, _IONBF, 0) != 0)

/* 案 B: 理由を付けた無視 */
/* 引数は固定で正しく、文書上の失敗条件に当たらない。失敗しても表示が遅れるだけで出力は失われない。 */
(void)setvbuf(stdout, NULL, _IONBF, 0);
