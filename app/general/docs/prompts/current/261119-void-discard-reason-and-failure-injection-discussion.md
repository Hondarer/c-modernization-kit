### Q-004 戻り値が失敗を表さない関数の呼び出しの扱い

**Status**

解決済み

**Question**

エラー詳細を記録する内部関数 (`cplat_internal_error_report_*`) の `(void)` の呼び出し 92 箇所を、どう扱いますか。

**Context**

`cplat` の 393 箇所のうち 92 箇所は、次の形の呼び出しです。

```c
/* app/cplat/prod/libsrc/cplat/crt/fcntl_format.c */
if (cplat_internal_vformat_path(filename, sizeof(filename), format, args, &format_error) != 0)
{
    (void)cplat_internal_error_report_errno(detail_out, format_error);
    return -1;
}
```

この関数は、エラー詳細を `detail_out` へ記録し、対応する結果コードを返します。戻り値は、`return cplat_internal_error_report_errno(...);` と書けるようにするための値であり、関数の失敗を表しません。  
上の例の呼び出し元は、結果コードではなく -1 を返す関数のため、戻り値を使いません。

5 分類は、失敗しうる呼び出しの扱いを決める規則です。この関数の呼び出しは、失敗の情報を破棄していません。一方、上流の最終仕様は「`(void)` で戻り値を破棄する呼び出しには、破棄する理由のコメントを常に付けます」と定めています。

各案を採用した場合の姿は次のとおりです。

```c
/* 案 A: 戻り値を返さない記録専用の内部関数を追加し、(void) をなくす (関数名は例) */
cplat_internal_error_set_errno(detail_out, format_error);
return -1;
```

```c
/* 案 B: 92 箇所のそれぞれに後置コメントを付ける */
(void)cplat_internal_error_report_errno(detail_out, format_error); /* 結果コードを返さない関数のため使わない */
return -1;
```

```c
/* 案 C: ファイルまたは関数の先頭に、まとまりの前置コメントを 1 つ付ける */
/* この関数は結果コードを返さないため、エラー詳細の記録の戻り値は使わない。 */
```

案 D は、ソースを変更しません。規範に「戻り値が失敗の情報でない関数の `(void)` には、理由コメントを求めない」と定め、関数の宣言の Doxygen に、戻り値を使わなくてよいことを記載します。

**Answer**

選択方式: 単一選択

- [x] A: (推奨) 戻り値を返さない記録専用の内部関数を追加し、92 箇所の `(void)` の呼び出しを置き換える。
- [ ] B: 92 箇所のそれぞれに後置コメントを付ける。
- [ ] C: ファイルまたは関数ごとに、まとまりの前置コメントを 1 つ付ける。
- [ ] D: 規範に例外を定め、92 箇所は変更しない。
- [ ] E: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

回答日時: 2026-11-19 08:36:03 JST (ファイルの更新時刻)

**Assessment**

回答 A により、戻り値を返さない記録専用の内部関数を追加し、92 箇所の `(void)` の呼び出しを置き換えることが確定しました。  
追加する関数の名前、対象とする関数の種類 (errno、Windows のエラー、Winsock のエラー、成功の記録)、テストからの参照の有無は、未確定です。洗い出しの結果とともに、別の確認項目として提示します。
