## 現物照合で追加確認した事項

`calc` の README は最小構成のサンプルと説明しており、レガシな書き方を保持する指示は確認できませんでした。  
`calcbase_subtract` は `calcbase_add(a, -1 * b, result)` を使い、コメントは関数呼び出しの実装例と説明しています。  
ただし、`a` と `b` がともに `INT_MIN` の場合、差は 0 でも途中の `-1 * b` が表現範囲を超えます。  
公開ヘッダーは計算結果のオーバーフロー検査を呼び出し側の責務としていますが、この途中計算の制約は説明していません。扱いを [Q-004](#q-004-calc-の減算例の扱い) で確認します。

`doxygen-sample/prod/include/enum.h` は、タグありとタグなしの列挙型をそれぞれ明示的に示しています。  
一方、両列挙型の `ZERO`、`ONE`、`TWO` は同じ名前であり、`code.h` の `reverseString` と使用例、`direction.h` の引数名も現行の報告どおりでした。  
記法を示す意図が明確な例と、名前などの修正候補を [Q-005](#q-005-doxygen-サンプルの規範との差の扱い) で分けます。

BL-018 の `struct-meta/print/print.c` は、`element_size` にかかわらず `sizeof(float)` または `sizeof(double)` を読み出します。  
`meta/validate.c` は整数の幅を検証しますが、浮動小数点の種別と要素幅の一致は検証していません。  
これは確保サイズの表記統一とは異なる、記述子検証と読み出しの整合性の問題として調査を続けます。

cplat 固有規範の「ラッパーがある関数の使用」は、単純な委譲やプラットフォーム差の吸収だけを目的とするラッパーについて、直接呼び出しを一律には禁止していません。  
BL-018 の `fprintf` などは、ラッパーがあるという理由だけで違反と確定せず、ラッパーの契約と適用条件を照合します。  
BL-008 の 187 箇所および BL-014 から BL-019 の全箇所の照合は未完了です。

共通コーディング規範の「型の命名規則」は、型名を snake_case とし、タグ名と typedef 名を一致させると定めています。

```c
typedef enum ENUM_SAMPLE1 { ENUM_SAMPLE1_ZERO, ENUM_SAMPLE1_ONE, ENUM_SAMPLE1_TWO } ENUM_SAMPLE1;
```

## Q-014 Win32 UTF-8 ラッパーの引数名を元の API に合わせる範囲

**Status**

**Question**

**Context**

- [ ] B: 現行の引数名を維持し、規範の文書は変更しない。
- [x] C: 元の Win32 API の引数名へ改名する。宣言、定義、Doxygen、mock、api-cheatsheet を変更する。
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)。

その他の回答 / 補足: Cだと思っている。WかUかの違いであり、関数シグネチャは引数名も含めて同じにし、必要ならWin32のUラッパーを全見直しして規範も対応させる

回答者: Tetsuo Honda (対話セッションの選択式の質問への回答を claude code が転記)。  
回答受付: 2026-11-10 09:29:45 JST、claude code。

**Assessment**

C の選択と補足を受け付けました。`win32/win32.h` が公開する UTF-8 ラッパー 14 関数すべてを対象に、引数名を対応する W 版の API の引数名と同じにします。元の報告は 4 関数だけを挙げていますが、補足の「全見直し」に従い、残る 10 関数も同じ規則で見直します。引数名の根拠は、Windows SDK のヘッダーと公式リファレンスです。

文字列の型が UTF-8 の `char` である点は、U 版と W 版の違いとして維持します。引数の個数、順序、文字列以外の型が W 版と異なるラッパーを確認した場合は、公開関数のシグネチャを変えずに引数名だけを対応付け、差異を記録してユーザーへ報告します。シグネチャ自体を W 版へ合わせる変更は、ABI に影響するため今回は行いません。

**Recommendation**

推奨: A。  
理由: 現行の引数名を変えなければ、宣言、定義、mock、文書の変更が不要です。元の API と同じ名前にそろえる要求がある場合は C が適します。
