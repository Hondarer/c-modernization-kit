## 現物照合で追加確認した事項

`calc` の README は最小構成のサンプルと説明しており、レガシな書き方を保持する指示は確認できませんでした。  
`calcbase_subtract` は `calcbase_add(a, -1 * b, result)` を使い、コメントは関数呼び出しの実装例と説明しています。  
ただし、`a` と `b` がともに `INT_MIN` の場合、差は 0 でも途中の `-1 * b` が表現範囲を超えます。  
公開ヘッダーは計算結果のオーバーフロー検査を呼び出し側の責務としていますが、この途中計算の制約は説明していません。扱いを [Q-004](#q-004-calc-の減算例の扱い) で確認します。

`doxygen-sample/prod/include/enum.h` は、タグありとタグなしの列挙型をそれぞれ明示的に示しています。  
一方、両列挙型の `ZERO`、`ONE`、`TWO` は同じ名前であり、`code.h` の `reverseString` と使用例、`direction.h` の引数名も現行の報告どおりでした。  
記法を示す意図が明確な例と、名前などの修正候補を [Q-005](#q-005-doxygen-サンプルの規範との差の扱い) で分けます。

BL-018 の `struct-meta/print/print.c` は、`element_size` にかかわらず `sizeof(float)` または `sizeof(double)` を読み出します。  
`meta/validate.c` は整数の幅を検証しますが、浮動小数点の種別と要素幅の一致は検証していません。  
これは確保サイズの表記統一とは異なる、記述子検証と読み出しの整合性の問題として調査を続けます。

cplat 固有規範の「ラッパーがある関数の使用」は、単純な委譲やプラットフォーム差の吸収だけを目的とするラッパーについて、直接呼び出しを一律には禁止していません。  
BL-018 の `fprintf` などは、ラッパーがあるという理由だけで違反と確定せず、ラッパーの契約と適用条件を照合します。

## Q-004 calc の減算例の扱い

- [ ] X: 意図不明 (詳細な質問内容に再生成すること)。

## Q-006 減算結果が int の範囲外の場合の返却規則

**Status**

解決済み

**Question**

`calcbase_subtract` の計算結果が `int` の範囲に収まらない場合、どの結果コードを返しますか。

**Context**

[Q-004](#q-004-calc-の減算例の扱い) の補足により、既存の関数呼び出し経路とリンケージを維持しつつ、オーバーフローへ対処します。  
[既存の定数](../../../../calc/prod/include/calc/calc_const.h) には `CALC_OK`、`CALC_ERR_UNKNOWN`、`CALC_ERR_INVALID_ARGUMENT` があり、範囲外専用のコードはありません。  
公開ヘッダーは範囲検査を呼び出し側の責務としているため、`INT_MAX - (-1)` や `INT_MIN - 1` を関数側で拒否する場合の返却規則を決める必要があります。

どちらの案でも、演算前に判定し、失敗時は出力先の値を変更しない方針を提案します。  
`INT_MIN - INT_MIN` のように差が表現可能な入力は、途中の符号反転で拒否せず成功させます。  
今回のオーバーフロー対処は `calcbase_subtract` に限定し、加算・乗算などの公開契約を一括変更する案ではありません。

**Answer**

選択方式: 単一選択

- [x] A: (推奨) 既存の `CALC_ERR_INVALID_ARGUMENT` を返す。範囲外の入力の扱いを減算の公開契約へ追記する。
- [ ] B: 範囲外専用の `CALC_ERR_OUT_OF_RANGE` を追加して返す。既存の結果コードの値は維持する。
- [ ] C: その他。返却規則と必要な変更範囲を補足欄へ記載する。
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)。

その他の回答 / 補足:

回答者: Tetsuo Honda (ユーザーによる検討文書への記入)。回答日時は未記録です。  
回答受付: 2026-11-10 04:38:23 JST、codex。

**Assessment**

A の選択を受け付けました。減算の演算前に範囲を検査し、範囲外は `CALC_ERR_INVALID_ARGUMENT` を返します。失敗時は出力先を変更しません。差が表現可能な `INT_MIN - INT_MIN` は成功させ、既存の加算呼び出しとリンケージを維持します。

**Recommendation**

理由: 表現できない結果になる入力を既存の引数エラーとして扱えば、公開定数の追加を避けつつ、演算前に失敗を通知できます。NULL と範囲超過を区別する要求がある場合は B が適します。
