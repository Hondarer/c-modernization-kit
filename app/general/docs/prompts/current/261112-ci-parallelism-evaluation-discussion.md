### Q-002 Windows の Run tests ステップの対処

**Status**

未回答

**Question**

Windows のジョブ (`build-and-test-windows`) の並列度の指定を、どう変えますか。

**Context**

Windows の Run tests ステップは、上げた後の 3 回 (132、137、118[分]) がすべて、上げる前の最大値 (103[分]) を超えています。Build ステップ (143、138、131[分]) は、上げる前の範囲 (109[分] 以上、中央値 149[分]) の中にあります。  
Run tests ステップでは、`MAKEFW_CPU_BUDGET` によって、テストのビルドの並列度と、テストを同時に実行する数の両方が 2 から 4 になっています。どちらが原因かは、ログから区別できません。

現状:

```yaml
      - name: Run tests
        env:
          MAKEFW_CPU_BUDGET: "8"
```

案 A (テストを同時に実行する数だけを 2 に戻す):

```yaml
      - name: Run tests
        env:
          MAKEFW_CPU_BUDGET: "8"
          MAKEFW_TEST_RUN_JOBS: "2"
```

案 B (Run tests ステップの指定を外す。Build ステップは `-j4` のまま):

```yaml
      - name: Run tests
        run: |
```

案 C は、Build と Run tests の両方から指定を外し、Windows を上げる前の状態に戻します。

**Answer**

選択方式: 単一選択

- [ ] A: Run tests ステップに `MAKEFW_TEST_RUN_JOBS: "2"` を追加する。
- [ ] B: (推奨) Run tests ステップの `MAKEFW_CPU_BUDGET` を外す。Build ステップは残す。
- [ ] C: Build と Run tests の両方から `MAKEFW_CPU_BUDGET` を外す。
- [ ] D: 変更せず、さらに実行を集める。
- [ ] E: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足:

**Recommendation**

推奨: B  
理由: Run tests ステップを、上げる前に 69 ～ 103[分] だった設定へ確実に戻せるためです。案 A は、原因がテストの同時実行数ではなくテストのビルドの並列度だった場合に効果がなく、確認にもう 1 回の実走 (約 5[時間]) が必要になります。Build ステップは悪化していないため、残します。  
制約: 案 B では、Run tests ステップが短くなる可能性 (テストのビルドだけを `-j4` にする構成) を試しません。

[Q-007](#q-007-windows-の対処の判定基準)、[Q-003](#q-003-bl-003-app-の中の時間の内訳の扱い)

- [ ] A: (推奨) 対処の後の実走 1 回で、全ジョブが成功し、Windows の Run tests ステップが 103[分] 以下であること。

- [ ] C: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足:

**Recommendation**

推奨: A  
理由: 上げる前と後の範囲が重なっていないため、1 回で区別できるためです。全ジョブの成功は、ほかの作業のコミットが原因で満たさない場合があります。その場合は、失敗の原因を分けて報告します。
