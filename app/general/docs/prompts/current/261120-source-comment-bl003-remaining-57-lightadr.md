## LADR-009 020 標準ストリームの FD 番号の不一致を失敗とする

決定者: Tetsuo Honda  
最終更新日: 2026-11-21

### 背景と課題

`console.c` の `reopen_crt_std_fd` は、標準ストリームの FD を閉じてから `_open_osfhandle` で開き直します。  
開き直した FD 番号が元の番号と一致しない場合に、失敗を返すかどうかを決める必要がありました。

### 得られた事実

- `_open_osfhandle` は、空いている最小の番号を返します (Windows SDK の UCRT のソースで確認)。
- 番号が一致しないのは、呼び出しの前に若番の標準 FD が閉じられている場合と、FD を閉じてから開き直すまでの間に別のスレッドがファイルを開いた場合です。
- 現在は、一致しない場合に診断ログだけを出して成功を返します。そのとき、`stdout` の FILE は閉じた FD を指したまま後続の処理へ進みます。
- 同じ種類の処理を持つ `elevated_process.c` は、失敗を返します。
- `cplat_console_attach_parent` は、`reopen_crt_std_fd` の失敗を破棄し、`CPLAT_OK` を返しています。標準ストリームの付け替えと開き直しで検出できる 5 種類の失敗は、すべて成功として返ります (`console.c`)。
- 機能仕様 (`docs/functional-spec/console.md`) は、「再接続後は、標準入力、標準出力、標準エラー出力を親コンソールへ接続します」と定めています。
- 公開ヘッダーは、`attached_out` を「戻り値が `CPLAT_OK` の場合のみ有効」と定めています。製品コードの呼び出し元は `service-sample` の 1 か所で、戻り値を破棄しています。

### 決定

FD 番号が一致しない場合、`reopen_crt_std_fd` は失敗を返します。開き直した FD は閉じません。閉じると、`SetStdHandle` へ渡した Win32 ハンドルも閉じるためです。  
公開 API の `cplat_console_attach_parent` は、標準ストリーム 3 本 (`stdout`、`stderr`、`stdin`) の付け替えと開き直しで検出できる失敗のすべてを、失敗として返します。  
対象の失敗は、`CONOUT$` / `CONIN$` を開けないこと、`SetStdHandle` の失敗、`_fileno` の失敗、`_open_osfhandle` の失敗、番号の不一致です。どれか 1 つでも失敗した場合は、3 本とも最後まで試みた後に、`CPLAT_ERR_UNKNOWN` を返します。  
`attached_out` は、戻り値によらず有効とします。コンソールへ接続できていれば 1、できていなければ 0 を格納します。  
割り当ての規則の根拠をコメントに書きます。直前の案件 (`void-discard-reason-and-failure-injection`) で付けた、この関数の戻り値の破棄の理由コメント 3 か所は、失敗を集計する処理へ置き換えます。  
公開ヘッダー、`api-cheatsheet.md`、機能仕様、既存のテストを合わせて直します。

決定者: Tetsuo Honda  
最終更新日: 2026-11-21

### 背景と課題

`cplat_internal_error_report_gai_error` は、`getaddrinfo` の失敗の要因 (cause) を細かく区別しますが、結果コードは `CPLAT_ERR_NOT_FOUND` と `CPLAT_ERR_UNKNOWN` の 2 値です。  
結果コードを分ける粒度を、決める必要がありました。

### 得られた事実

- errno を報告する関数と Winsock のエラーを報告する関数は、メモリ不足を `CPLAT_ERR_OUT_OF_MEMORY`、一時的な失敗を `CPLAT_ERR_BUSY` へ変換します。`getaddrinfo` の報告だけが、この対応と一致していません。
- 呼び出し元は `cplat_ipv4_resolve` だけで、検索の条件 (アドレス ファミリー、ソケット種別、フラグ) を内部で固定しています。`EAI_FAMILY`、`EAI_SOCKTYPE`、`EAI_BADFLAGS` は、利用者の引数からは発生しません。
- `app/porter` は、`CPLAT_ERR_INVALID_ARGUMENT` 以外をすべて同じエラーへ変換します。
- `endpoint.h` の `@return` に、`CPLAT_ERR_NOT_FOUND` が抜けています。
- `CPLAT_ERR_NOT_FOUND` は、`EAI_*` の値ではなく、要因で判定しています。`EAI_SYSTEM` の要因は errno から決まり、errno が `ENOENT` などの場合は、現在も `CPLAT_ERR_NOT_FOUND` が返ります (`error.c` の `cplat_internal_error_report_gai_error` と `error_cause_from_gai_error`)。Q-012 の Context の表は、この点が正確ではありませんでした。

### 決定

名前解決の失敗の結果コードは、要因 (cause) で判定します。  
要因がメモリ不足の場合は `CPLAT_ERR_OUT_OF_MEMORY`、一時的な失敗の場合は `CPLAT_ERR_BUSY`、見つからない場合は `CPLAT_ERR_NOT_FOUND` を返します。ほかは `CPLAT_ERR_UNKNOWN` のままとします。  
`EAI_MEMORY` と `EAI_AGAIN` に加えて、Linux の `EAI_SYSTEM` で errno がメモリ不足 (`ENOMEM`) または一時的な失敗 (`EAGAIN`、`EBUSY` など) を示す場合も、同じ結果コードになります。  
`endpoint.h` の `@return` に `CPLAT_ERR_NOT_FOUND` を追記し、`api-cheatsheet.md`、テスト、`app/porter` の該当コメントを直します。

- 実装の段階で、`app/cplat` の `platform.h` だけは `static_assert` (`<assert.h>`) へ統一できないことが分かりました (2026-11-22)。ほとんどの翻訳単位が最初に取り込むヘッダーで `<assert.h>` を取り込むと、glibc の機能検査マクロが `_GNU_SOURCE` の定義より前に確定し、Linux のビルドが失敗します。`platform.h` は C で `_Static_assert` を使う形に戻し、規範の扱いは残課題一覧の BL-039 に記録しました。

### 決定

コンパイル時の整数定数は、`#define` で定義します。13 個の定数も、`#define` で定義します。  
共通のコーディング規範を改め、名前付きの整数定数の節を加えます。`#define` を正とする理由 (C では `static const` が定数式にならず、`enum` は `int` に限られる) を、規範へ書きます。  
新しい規範には、正しさを強化する 4 つの規則を入れます。型を合わせること、制約を `static_assert` で検査すること、同じ値を 2 か所に書かず役割と単位を書くこと、意味を持つ直値を書かないこと (例外を定める) です。  
全 app の製品コード (`prod` 配下の `.c` と `.h`) について、新しい規範への適合を確認し、不適合をこの案件で直します。直すと動作や公開の契約が変わる箇所と、判断が要る箇所は、一覧にして確認を受けます。テスト コードと framework は対象外です。テスト コードでは、期待値と入力を直値で書くことが推奨されるためです。`app/porter` は、フロー制御の後に確認して直します。  
規範の文面は、最終仕様に載せます。  
容量を拡張する倍率と、件数に掛ける係数は、名前付き定数にします (039 と 181 の決定を改めます)。  
文字列リテラルの長さから決まる値は、直値で書かず、`sizeof(リテラル) - 1`、またはリテラルと長さを組にした名前付き定数で求めます。  
文字符号の規格が定める値は、内部ヘッダーの名前付き定数 (規格の `see:` 付き) へ集約します。  
`app/cplat` の公開ヘッダーの、大きさと個数を表す定数 7 個に、`U` を付けます。リポジトリの中の利用箇所は、確かめて直します。  
互いに排他的な値の集合は、内部も公開ヘッダーも、`enum` にします。公開の関数の引数と構造体のメンバーの型は、`int` のままとします。

プリプロセッサで変換できない重複 (GUID の数値の組と文字列) は、互いの場所をコメントで書き、一致を確かめるテストを足します。  
コメントの内訳と合わない余裕を持つバッファーの大きさは、内訳の各項目を定数にし、合計の式で定義します。  
C++ の製品コードでは、定数を `constexpr` (ファイルの中だけで使うものは無名の名前空間) で定義します。R1 から R5 の規則は、C と同じく適用します。  
`POTR_NACK_DEDUP_SLOTS` の値とコメントの食い違いは、履歴を調べて、意図した値が分かる場合はその値へ合わせます。分からない場合は、値 8 を保ち、コメントを事実へ直して、残課題一覧へ記録します。

## LADR-032 BL-006 昇格の出力の受け渡しを名前付きパイプへ変える

決定者: Tetsuo Honda  
最終更新日: 2026-11-21

### 背景と課題

昇格したプロセスは、親プロセスを `OpenProcess` で開いてパイプを複製します。別のアカウントの資格情報で昇格した場合に、開けない可能性があります。対処の範囲を決める必要がありました。

### 得られた事実

- 開けない場合、失敗は検出されて終了コードで返りますが、利用者には原因が何も表示されません。
- 別のアカウントでの昇格で実際に失敗するかは、資料からは決まらず、標準ユーザーと別の管理者アカウントがある実機でしか確かめられません。

### 決定

無名パイプと `OpenProcess` をやめ、名前付きパイプで受け渡す方式へ変えます。  
利用側 (`eventlog-register`) は、昇格したプロセスが 0 以外で終了した場合に、終了コード付きの診断を出します。公開ヘッダー、README、`api-cheatsheet.md` に、失敗時の動作と確認済みの範囲を書きます。  
パイプ名の先取りと、なりすましの防止は、最終仕様で定めます。実装の後に、実機での確認をユーザーへ依頼します。042 で決めたコメントの文面は、新しい方式に合わせて書き直します。  
昇格したプロセスがパイプへ接続しないまま終了した場合と、読み取りが相手の終了以外の理由で失敗した場合は、`CPLAT_ERR_UNKNOWN` を返し、終了コードへ失敗の値を格納します。  
名前付きパイプには、アクセス許可の明示 (LocalSystem、Administrators、呼び出し元のユーザー)、匿名の偽装レベル、接続したプロセスの照合の 3 つの保護を入れます。

## LADR-034 BL-007 起動の失敗をサービスの起動の失敗にし、watchdog を on_run の生存に結び付ける

決定者: Tetsuo Honda  
最終更新日: 2026-11-21

### 背景と課題

`service-sample` の Linux は、watchdog の通知を担うイベント監視スレッドの起動に失敗しても、起動の完了を通知します。また、通知はスレッドが自動で送るため、サービスの本体 (`on_run`) の停止を検知しません。対処の範囲を決める必要がありました。

### 得られた事実

- 起動に失敗すると、30 [s] 後に watchdog の時間切れで強制終了され、再起動を繰り返します。
- スレッドの中の初期化の失敗は、起動側へ返っていません。

### 決定

イベント監視スレッドの起動と、スレッドの中の必須の初期化の失敗を、サービスの起動の失敗にします。  
watchdog の通知を、`on_run` の生存に結び付けます。`on_run` が周期的に `svc_wait_for_stop()` を呼んでいる間だけ、通知を送ります。`on_run` の契約に、この周期の条件を加えます。  
`on_start` と `on_stop` の間の扱いは、最終仕様で定めます。157 で決めた文面は、書き直します。  
`on_run` の生存は、`svc_wait_for_stop()` で待機している間と、呼び出しを続けている間とします。待機の時間に制約はありません。  
`on_reload` がある場合だけ、unit へ `ExecReload=` を書き込みます。SIGHUP のハンドラーは常に設定し、`on_reload` がない場合は WARNING のトレースを出して何もしません。リロードの準備の失敗は、起動の失敗にします。  
Linux の `on_event` と `on_reload` の配送は、起動の完了の通知の後から `on_run` が戻るまでに限ります。
