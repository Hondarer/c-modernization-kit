## 照合で確認した事実

### 波括弧の省略

`tcp_write_all_paths` には、本体が `continue` だけの `if` が 2 箇所あります。  
残課題が指していた 149 行は現在も 148 行から 149 行です。  
179 行として記録されていた方は、現在は 181 行から 182 行です。

```c
if (ctx->tcp_conn_fd[i] == CPLAT_INVALID_SOCKET)
    continue;
```

```c
if (!skipped[i])
    continue;
```

同じ関数の他の `if` は波括弧を付けています。  
同じファイルには、ほかに波括弧のない `if` が 3 箇所あります。  
`flush_packed_peer` の 466 行から 467 行、`send_packed_peer_mode` の 511 行から 514 行です。  
porter の他の `.c` にも、同じ形の `if` が複数残っています。

共通コーディング規範、cplat のコーディング規範、porter のコーディング規範には、単文の `if` に波括弧を必須とする文はありません。  
規範中の望ましい例は波括弧を付けています。  
`.clang-format` の実効設定は `InsertBraces: false` であり、波括弧の追加は整形では行われません。  
`AllowShortIfStatementsOnASingleLine: Never` は、`if` と本体を同一行に置くことを避ける設定です。

### bench-tracer の積

`cplat_parse_int` は、各引数が `int` に収まることを検査します。  
既定値はプロセス数 16、メッセージ数 1000 です。  
0 以下は usage を標準エラー出力へ書いて 1 で終了します。  
ファイル先頭の説明は、成功を 0、失敗を 1 としています。

`int` に収まる 2 つの正数でも、積は `int` を超えることがあります。  
その積は、次の 2 箇所で符号付きの乗算として評価されます。

- `main` の `measure_filtered(messages * processes)` (294 行)
- `measure_files` の `printf` に渡す `processes * messages` (232 行)

`measure_filtered` の引数は `int` です。  
232 行の `%d` も `int` の積を印字します。  
同じ関数の除算 `(uint64_t)processes * (uint64_t)messages` は、乗算の前に広い型へ変換しています。  
worker 経路はメッセージ数を単独の `int` として使い、積は計算しません。

共通コーディング規範の「符号付き整数のオーバーフロー」は、演算の前に、結果が型の範囲へ収まることを検査する、としています。  
プロセス数だけが大きい場合 (メッセージ数が 1) は、積が `int` に収まっても、子プロセスをその個数だけ起動します。  
プロセス数やメッセージ数の個別上限を定めた文書は、見つけていません。

既存の `bench_tracerTest.rejects_invalid_numeric_arguments` は、空文字、不正文字、`int` へ収まらない 1 引数を終了値 1 で拒否します。  
両方とも `int` に収まり、積だけが `int` を超える組は検査していません。

### 呼び出し例と確認タグ

`cplat_mmap_attach` の公開宣言は 5 引数で、第 5 引数 `detail_out` は NULL なら詳細を返さない、と書いてあります。  
cplat のコーディング規範 97 行の例は 4 引数です。  
同じファイル内の `cplat_mmap_attach` の呼び出しは、この 1 箇所です。  
この節の主題は、結果コードを `CPLAT_OK` と比較することです。

`clock_failure_preserves_timestamp` の Assert には確認タグ付きの `EXPECT_EQ` が 2 行あり、ナノ秒の `EXPECT_EQ(456, resolved.tv_nsec)` にはタグがありません。  
テスト フェーズの正本は、Assert の各 `EXPECT_*` に `[確認_正常系]` または `[確認_異常系]` を一対一で付ける、としています。  
説明文は、マクロの判定をそのまま書き、必要なときだけ括弧内に総合期待を続けます。  
同じテストの秒の確認は、判定そのものより短い「取得失敗前の時刻を保持すること。」になっています。
