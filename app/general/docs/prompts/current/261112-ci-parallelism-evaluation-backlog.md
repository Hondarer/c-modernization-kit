## BL-001 docs ジョブの make docs の時間の短縮

### 概要と問題点

- **現状の事象**: GitHub Actions の `docs` ジョブは、`make doxy && make docs` の文書の生成に約 1[時間] かかります。並列度を上げた後の実行では 64、64、89[分]、この案件の確認に使った実行 43429817821 では、文書の生成のステップが 58[分] でした。
- **本来あるべき姿**: 文書の生成が、必要な時間で終わること。現在は、最も短いビルドとテストのジョブより短いため、実行全体の時間には影響していません。

### 経緯と見送り理由

- **摘出契機**: 過去 backlog からの引き継ぎ。`../past/261111-ci-docs-job-split-backlog.md` の BL-002 から、`261111-ci-time-backlog-followup-backlog.md` の BL-005 を経て引き継ぎました。
- **今回の見送り理由**: 短くしても実行全体の時間が変わらないためです。ユーザーの回答 (Q-005、2026-11-13) は「次回以降で詳細に検討したい」です。
- **継続作業での経緯と対処**: (未対処)

### 影響範囲とリスク

- **影響対象**: `.github/workflows/ci.yml` の `docs` ジョブ、`framework/doxyfw`、`framework/docsfw`、GitHub Pages への発行までの時間。
- **放置した場合のリスク**: ビルドとテストのジョブが短くなった場合に、`docs` ジョブが実行全体の時間を決めるようになります。

### 推奨される対応策

- **恒久対応案**: まず、`make doxy` と `make docs` の内訳 (app ごと、生成の種類ごと) をログから測り、時間の大きい処理を特定します。そのうえで、並列化や不要な生成の削減を検討します。
