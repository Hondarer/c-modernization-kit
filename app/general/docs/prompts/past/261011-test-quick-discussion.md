## 現行実装から確認した事実

[makemain.mk](../../../../../framework/makefw/makefiles/makemain.mk) はビルドと実行を分けています。  
実行フェーズでは再帰 make に `-j1` を指定しますが、末端の実行は [run_ordered_subdir_target.sh](../../../../../framework/makefw/bin_internal/run_ordered_subdir_target.sh) が並列度を制御します。  
app 集約では依存関係を考慮した実行とカバレッジの集約があります。

[exec_test_c_cpp.sh](../../../../../framework/testfw/bin_internal/exec_test_c_cpp.sh) はテスト一覧を取得したあと、ケース名ごとにフィルターを指定して起動し、エビデンスとカバレッジを生成します。  
末端の `test.stamp` と app の `make_test.stamp` は通常テストを省略する条件に使われます。  
GCC の対象ソースには計測処理が組み込まれるため、レポート生成だけを止めても計測データへの書き込みは残る可能性があります。

[exec_test_dotnet.sh](../../../../../framework/testfw/bin_internal/exec_test_dotnet.sh) はすでにまとめて実行し、TRX と Markdown の結果を生成します。  
.NET 対応は回答で確定しました。通常スクリプトの TRX・エビデンス生成を省く経路を変更候補とし、プロジェクト固有のカバレッジ設定との整合は最終仕様の作成時に確認します。

**Question**

**Context**

GCC は GCOV_PREFIX と GCOV_PREFIX_STRIP で保存先を変更できます。計測処理や一時的な .gcda の生成は残りますが、通常の obj 配下の .gcda を更新しません。元の [Q-005](#q-005-カバレッジ省略の深さ) では別ビルドを推奨していましたが、[Q-007](#q-007-ビルドの実施) の補足に従い再ビルド不要の方式へ具体化しました。

GCC 8.5.0 の小さな C プログラムを /tmp に作成し、元の .gcda のハッシュが変わらず、一時領域へ .gcda が生成されること、その後の通常起動では元のファイルが更新されることを確認しました。  
実際の app の子プロセス・共有ライブラリ・異常終了を含む確認は、実装承認後の局所検証で行います。

A の起動例では、通常の実行ファイルへの引数を変えず、環境変数だけを実行の子プロセスへ適用します。

```sh
GCOV_PREFIX=/tmp/test-quick-gcov-example GCOV_PREFIX_STRIP=0 ./bin/exampleTest
```

B では、同じ実行ファイルでも一時ファイルの生成まで禁止します。

```text
通常の obj/*.gcda: 変更禁止
一時領域の *.gcda: 生成禁止
再ビルド: 禁止
この条件を満たす実行方式: 未確認
```

Table: 推奨要件を選んだ場合の受入条件と局所検証候補

| --- | --- |

| ツール依存 | 集計・カバレッジ用ツールを呼ばず、それらがない環境でも簡易実行できること |
