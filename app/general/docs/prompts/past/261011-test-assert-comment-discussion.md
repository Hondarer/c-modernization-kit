## 背景

### 依頼の趣旨

`EXPECT_EQ(A, B)` が行う判定は「B が A と一致すること」という単純なものです。  
ところが確認コメントには、判定そのものではなく、その判定から導かれる総合的な期待 (以下「総合期待」) だけが書かれているものがあります。  
例えば `EXPECT_EQ(1u, added_table)` に「追加でテーブル世代が 1 増えること。」と書くと、コードは「1 と一致すること」を判定しているのに、コメントは「増えること」という差分を述べています。

製品コードのコメントは、コードの意図や理由を補うものです。  
これに対しテストの手順と確認の説明は、コードが何をしているかを直接説明することを主体にします。  
そこで、確認コメントはまず判定の内容を平易な日本語で表し、必要な場合に限り続けて総合期待を書く方針とします。

### 確認コメントが表示される場所

確認コメントは、テスト結果 `results.md` の `### 確認` 節に箇条書きで転記されます。  
同じ `results.md` の「テスト コード」節にはテスト関数のコードがそのまま載るため、読み手はコメントとマクロを突き合わせて読みます。  
コメントが総合期待だけだと、どのマクロのどの値を見ればよいかを読み手が推測する必要があります。

```markdown
### 確認内容 (正常系:5)

- 追加が成功すること。
- c が見つかること。
- 時刻ではなく世代が古い a(レコード1)が再利用されたこと。
- `cplat_hashtable_get_status(ht, 2, &status_b)` の戻り値が `CPLAT_OK` であること。
- b(レコード2)は変更されず削除中のままであること。
```

## 修正方針 (叩き台)

版 1 の叩き台に、ユーザーの添削と [Q-001](#q-001-判定の主語の書き方) 〜 [Q-008](#q-008-入力条件の置き場所) の回答を反映した方針です。

1. 1 文目に、マクロが行う判定を「〜であること。」の形で書きます。マクロの種類に応じて次の表の述語を使います。
2. 主語は、関数の戻り値なら「関数名 の戻り値」、それ以外は変数名や式とします。戻り値を変数で受けず、マクロの引数に関数呼び出しを直接書く場合も同じです ([Q-001](#q-001-判定の主語の書き方))。
3. 同じ関数を時点や入力を変えて呼び分けている場合は、その条件を主語の前に置きます (例: 「追加後の …」) ([Q-008](#q-008-入力条件の置き場所))。
4. 識別子と値はバッククォートで囲みません ([Q-002](#q-002-識別子の書式))。
5. 総合期待は、1 文目だけでは判定の意図が読み取れない場合に書きます ([Q-005](#q-005-総合期待を書く条件))。1 文目の句点の直後に、半角の括弧で囲み、「〜ことの確認」で終えます。括弧の後に句点は付けません ([Q-003](#q-003-総合期待のつなぎ方)、[Q-004](#q-004-総合期待の文末))。
6. `[確認_*]`、`[Pre-Assert確認_*]`、`[状態確認]` のすべてに適用します ([Q-006](#q-006-適用するタグの範囲))。ただし `[状態確認]` には総合期待を書きません ([Q-009](#q-009-状態確認の総合期待と括弧の入れ子))。
7. 関数名の後に `()` を付けます ([Q-017](#q-017-関数名の後の括弧))。
8. `EXPECT_CALL` で `_` 以外の引数条件を指定している場合は、「X を指定して」で列挙します ([Q-016](#q-016-呼び出しの引数条件の書き方))。マッチャーで指定した引数は意味を日本語で書きます ([Q-019](#q-019-引数マッチャーの書き方))。
9. `[Pre-Assert確認_*]` を `[Pre-Assert手順]` より先に書きます。この順序を文書に規則として追加し、逆順の箇所は書き換えます ([Q-016](#q-016-呼び出しの引数条件の書き方) の補足、[Q-018](#q-018-pre-assert-の記載順の規則))。

```cpp
EXPECT_EQ(1u, added_table); // [確認_正常系] - added_table が 1 であること。(追加でテーブル世代が 0 から 1 増えたことの確認)
EXPECT_EQ(CPLAT_OK, actual_ret_added_table); // [確認_正常系] - 追加後の cplat_hashtable_get_table_generation() の戻り値が CPLAT_OK であること。
```

Table: マクロごとの 1 文目の述語

| マクロ | 1 文目の述語 |
| --- | --- |
| `EXPECT_EQ(A, B)` | B が A であること。 |
| `EXPECT_NE(A, B)` | B が A 以外であること。 |
| `EXPECT_LT(A, B)` / `EXPECT_GT(A, B)` | A が B より小さいこと。/ A が B より大きいこと。 |
| `EXPECT_TRUE(X)` / `EXPECT_FALSE(X)` | X が true であること。/ X が false であること。 |
| `EXPECT_STREQ(A, B)` | B が A であること。 |
| `EXPECT_CALL(m, f(...)).Times(0)` | f() が呼び出されないこと。 |
| `EXPECT_CALL(m, f(...))` (回数指定なし、`WillOnce` 1 個) | f() が 1 回呼び出されること。 |

### 例 1: 戻り値の判定を「〜を読めること」と書いている

最も多い型です。

[hashtableGenerationTest.cc:129](../../../../../app/cplat/test/src/libcplatTest/hashtable/hashtableTest/hashtableGenerationTest.cc#L129)

```cpp
// 現状
EXPECT_EQ(CPLAT_OK, actual_ret_added_table); // [確認_正常系] - 追加後にテーブル世代を読めること。
```


- 修正案の補足: 同じ関数を追加後、更新後、削除後に 3 回呼ぶため、「追加後の」で区別しています。区別の書き方は [Q-001](#q-001-判定の主語の書き方) と [Q-008](#q-008-入力条件の置き場所) に関係します。

**Question**

**Context**

テストでは `int actual_ret_added_table = cplat_hashtable_get_table_generation(ht, &added_table);` のように、関数の戻り値を変数で受けてから判定します。  
主語に関数名を書くか変数名を書くかで、読み手に伝わる情報が変わります。  
出力引数やループで作った変数 (例: `added_table`、`in_range`) は、対応する関数が 1 つに決まらないため変数名を書く前提です。

```cpp
// 案 A: 関数名の戻り値と書く (既存の直接の書き方 1,575 件と同じ)
EXPECT_EQ(CPLAT_OK, actual_ret_added_table); // [確認_正常系] - 追加後の cplat_hashtable_get_table_generation の戻り値が CPLAT_OK であること。

// 案 B: 変数名を書く (マクロの引数と字面が一致する)
EXPECT_EQ(CPLAT_OK, actual_ret_added_table); // [確認_正常系] - actual_ret_added_table が CPLAT_OK であること。

// 案 C: 両方を書く
EXPECT_EQ(CPLAT_OK, actual_ret_added_table); // [確認_正常系] - actual_ret_added_table (cplat_hashtable_get_table_generation の戻り値) が CPLAT_OK であること。
```

案 A は何を呼んだ結果かが分かりますが、同じ関数を複数回呼ぶ場合は「追加後の」などで区別が必要です。
