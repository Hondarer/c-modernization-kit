**Status**

解決済み

**Question**

Windows のジョブ (`build-and-test-windows`) の並列度の指定を、どう変えますか。

**Context**

```yaml
      - name: Run tests
        env:

```

```yaml
      - name: Run tests

          MAKEFW_TEST_RUN_JOBS: "2"
```

```yaml
      - name: Run tests
```

### Q-009 時間を表示する単位

**Status**

解決済み

**Question**

経過時間を、どの単位で表示しますか。

**Context**

[Q-003](#q-003-bl-003-app-の中の時間の内訳の扱い) の回答を受けて、表示する箇所を調べました。

- app を順に実行するスクリプト (`framework/makefw/bin_internal/run_ordered_subdir_target.sh`) は、app の開始と終了を `INFO: dispatch`、`INFO: done` の行で表示しています。経過時間は表示していません。
- app の中の段階 (`prod` のビルド、`test` のビルド、テストの実行) は、app 直下の `makefile` が子の `make` として順に実行します。この `makefile` は、makefw のテンプレート (`makefiles/__each_app_template.mk`) の複製で、17 個の app にあります。複製は `bin/update_template_makefiles.py` で同期します。
- app のリポジトリはサブモジュールに分かれているため、テンプレートを変えると、複製を持つ各リポジトリのコミットと push が必要です。

案 A (スクリプトだけを変える。makefw の変更だけで済む):

```text
INFO: done [3/17] app/cplat rc=0 elapsed=49:12
```

案 B (テンプレートも変え、app の中の段階ごとに表示する):

```text
make -C prod
...
INFO: app/cplat prod elapsed=00:18
make -C test
...
INFO: app/cplat test elapsed=48:40
```

`make test` では、テストの実行 (`make -C test _test_run`) の後にも同じ形式の行を表示します。  
案 B は、app 直下で `make` を実行した場合にも表示されます。

コンパイルとリンクを分けた時間は、どの案でも表示しません。末端の makefile テンプレートの規則ごとに時刻を取る必要があり、変更が大きくなるためです。

**Answer**

選択方式: 単一選択

- [ ] A: app ごとの経過時間だけを、`INFO: done` の行に表示する (makefw だけを変更)。
- [x] B: (推奨) 案 A に加えて、app の中の段階 (`prod`、`test`、テストの実行) ごとに表示する (makefw と、17 個の app の `makefile` を変更)。
- [ ] C: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足: Windows での性能低下が発生しないようにプロセス生成数を抑えて実装し、かつ、ローカルで性能劣化が無いか局所検証して実装のこと。

回答者: Tetsuo Honda  
回答日時: 2026-11-13 06:56:51 JST (検討用 Markdown の保存時刻)

**Assessment**

案 B が確定しました。補足の 2 つの条件を、最終仕様の実装条件と受入条件に含めます。  
1 つ目の条件 (プロセスの生成数を抑える) は、シェルの組み込み機能だけで経過時間を求めることで満たします。テンプレートのレシピでは bash の変数 `SECONDS` と組み込みの `printf` を使い、`date` などの外部コマンドを起動しません。スクリプトでは、すでに取得している時刻 (`now_seconds` の戻り値) を使い回し、時刻の取得を増やしません。  
2 つ目の条件 (手元での性能の確認) は、変更の前後で、ビルド済みの app の `make` の所要時間を Windows の手元で比べて確認します。  
複製を持つ app は、サブモジュールが 7 個 (cjson、cplat、lua、openssl、porter、sqlite、zlib)、親リポジトリの中が 10 個です。この案を選んだことにより、[Q-008](#q-008-コミットと-push-の許可) の許可をこれらのリポジトリにも適用します。

**Recommendation**

推奨: B  
理由: BL-003 が求めていたのは app の中の内訳で、案 A では得られないためです。app ごとの時間は、今のログでも `dispatch` と `done` の行の時刻の差から求められます。  
制約: 案 B は、複製を持つ app のリポジトリ (サブモジュール) それぞれにコミットと push が必要です。[Q-008](#q-008-コミットと-push-の許可) の許可を、これらのリポジトリにも適用してよい場合に選んでください。
