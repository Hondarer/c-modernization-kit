## エビデンスの生成を省き、既存テストで回帰を確認します

`make test-quick` は、通常のテストと同じビルド成果物を使って回帰を確認するターゲットです。  
必要な差分ビルドを行ったあと、対象の有効なテストをまとめて実行します。  
フレームワークと標準テスト ランナーによるエビデンス・レポートの生成とカバレッジの集計を省略します。

対象は C/C++ の Google Test と .NET のテストです。  
単体テスト・統合テストの区分では自動除外しません。  
専用の少数テスト集合や専用ビルド構成は設けません。

## 通常 test と同じ階層から呼び出します

通常の `make test` が対応する app 集約、app 直下、test 配下の中間ディレクトリ、テスト実行ファイルのある末端から呼び出せるようにします。  
指定した階層の対象を巡回し、同じ実行ファイルを重複実行しません。

```sh
make -C app test-quick
make -C app/example test-quick
make -C app/example/test test-quick
make -C app/example/test/src/exampleTest test-quick
```

例の `example` は呼び出し階層を示す名前です。  
依存 app の製品・モック・ライブラリなど、対象のビルドとリンクに必要な依存関係を維持します。

## ビルド構成を変えず、テストの実行は成功スタンプで省略しません

ビルド フェーズと実行フェーズを分け、ビルド失敗時にはテストを開始しません。  
コンパイル・リンクのオプション、成果物の配置、ABI は通常のテストと同じにします。  
ソースが変わっていれば必要な差分ビルドを行い、変更がなければ既存の成果物を使用します。  
簡易実行への切り替えを理由とした再ビルドは行いません。

`test.stamp` と `make_test.stamp` による変更なしの実行省略は適用しません。  
簡易テスト用の成功スタンプも設けず、実行対象となったテストは呼び出すたびに実行します。  
簡易テストの成功で通常テストの成功スタンプを更新しません。

保証済み app の `assured.stamp` による省略は、通常の `make test` と同じ条件で適用します。  
`SKIP_BUILD`、`SKIP_TEST`、`NO_LINK` の明示的な設定も尊重し、実行しなかった理由を表示します。  
コンパイルのみの対象と非テストのディレクトリは、実行対象がないことをテスト失敗として扱いません。

## 実行ファイルごとにテストをまとめて起動します

C/C++ は、各実行ファイルについてテスト実行用プロセスを 1 回起動し、対象ケースをまとめて実行します。  
ケース単位に分けた起動と、状態共有による失敗を隠すための個別再実行は行いません。  
Google Test の death test などが内部で作る子プロセスは、起動回数の制約に含めません。

.NET は、対象のテスト プロジェクトのビルド後に、テスト実行コマンドで対象ケースをまとめて実行します。  
簡易実行のためにケースごとにテスト ホストを起動する方式は採用しません。  
TRX を生成・解析する通常のエビデンス処理を、簡易実行の成否判定に使用しません。

`pre-test` と `post-test` の既存フックを尊重します。  
フックとテスト本来のファイル操作は維持します。  
独自 main を持つ対象でも、対象の実行前提と終了状態を維持します。

## 言語ごとのフィルターをそのまま受け付けます

Table: 簡易テストの言語別フィルター入力

| 対象 | 変数 | 指定する構文 |
| --- | --- | --- |
| C/C++ | `GTEST_FILTER` | Google Test のフィルター構文 |
| .NET | `DOTNET_TEST_FILTER` | .NET の `--filter` に渡す式 |

各変数は make 引数と環境変数の両方で受け付けます。  
言語間で構文を変換せず、対象言語の変数をその実行経路へ渡します。  
C/C++ は未定義と空文字を区別し、通常の Google Test と同じ意味を維持します。

```sh
make test-quick GTEST_FILTER='ParserTest.*-ParserTest.LongCase'
make test-quick DOTNET_TEST_FILTER='FullyQualifiedName~Parser'
```

通常の有効ケースを既定の対象とし、Google Test の無効化されたケースは通常の既定動作に従います。  
フィルター適用後に正常に判定された実行対象が 0 件なら、そのことを表示して成功とします。  
起動失敗やテスト ホストの障害は、正常な 0 件と区別して失敗とします。

## カバレッジの集計を省き、GCC の計測出力を隔離します

gcov、gcovr、lcov、OpenCppCoverage、カバレッジの結合処理を簡易実行のために起動しません。  
Markdown のエビデンス生成器、確認件数の集計器、ソース抜粋処理も簡易実行経路で呼び出しません。  
これらの集計・生成用ツールを、簡易実行の必須依存にしません。

Linux/GCC では、通常の計測済み実行ファイルを利用します。  
実行ごとに一意な一時ディレクトリを作成し、`GCOV_PREFIX` と `GCOV_PREFIX_STRIP=0` を子プロセスへ設定して、簡易実行分の `.gcda` をそこへ隔離します。  
子プロセスが通常終了・失敗・異常終了した場合も、ランナーが回収できる一時領域を破棄します。  
呼び出し元の環境設定は変更せず、並列実行で保存先を共有しません。  
一時データは通常テストの計測ディレクトリへ移動・結合しません。

> [!NOTE]
> カバレッジ計測用の命令と一時的な `.gcda` の書き込みは残ります。
> 保存先を変える方式なので、通常と同じビルド成果物を使ったまま、既存の計測データへの簡易実行分の混入を防ぎます。
> 保存先変更の仕様は [GCC の公式文書](https://gcc.gnu.org/onlinedocs/gcc-8.5.0/gcc/Cross-profiling.html) に従います。

Windows/MSVC では OpenCppCoverage を起動せず、テスト実行ファイルを直接実行します。  
GCC の保存先変更設定を Windows/MSVC の実行へ適用する必要はありません。

## 既存結果を保存し、簡易成功を通常成功へ流用しません

フレームワークは既存の `results`、`coverage`、通常用の `.gcda`、`test.stamp`、`make_test.stamp` を簡易実行のために更新・削除しません。  
標準ランナーのファイル出力指定も抑止し、指定を無視したことを警告します。  
Google Test の `GTEST_OUTPUT` 等、および .NET のレポートやカバレッジ指定に対してこの方針を適用します。  
テスト自体の期待するファイル入出力やフックの処理は抑止対象に含めません。

次回の通常 `make test` は、簡易実行の計測データや成功状態を通常テストの結果として利用しません。  
変更後の差分ビルドと通常テストの既存の省略判定も含め、切り替え時の整合性を確認します。

実装後の検証で既存結果の保存に未対応の不足が判明した場合は、影響、再現条件、次回の通常テストへの影響、恒久対応案を残課題として記録します。  
保存不足だけを理由とした一律の実行停止や、自動的な既存結果の全削除を必須の動作にしません。

## 失敗を返し、残りの実行ファイルも確認します

ビルド失敗、テスト失敗、起動失敗、実行ファイル不在、必要な共有ライブラリの不足、異常終了は、呼び出し元の make の非 0 終了へ反映します。  
make の終了コードと子プロセスの終了コードの数値一致までは要件にしません。  
出力の変換や表示・集約処理で、本来の失敗を成功に変えません。

実行フェーズで一つの実行ファイルが失敗しても、残りの実行ファイルを実行し、全体の結果を失敗とします。  
クラッシュした実行ファイル内の未実行ケースを補うための再起動は行いません。  
既存の実行ファイル間・app 間の並列度制御、CPU 予算、コンソール出力順序を維持します。  
正常に対象 0 件と判定された場合、明示除外、保証済み app の省略は、それぞれの理由を表示します。

## Linux と Windows の実行前提を維持します

Linux/GCC と Windows/MSVC の両方に対応します。  
通常の実行に必要なライブラリ探索、文字コード、コンソール設定、スタック設定を維持します。  
空白を含む配置でも実行ファイルと引数を正しく渡し、日本語のコンソール出力を維持します。  
通常 test と同じ末端で同時実行した場合の共有ファイル競合を局所検証で確認します。

| 両 framework の `bin_test/` | テンプレートと実行処理の局所テスト |
| `framework/testfw/docs/how-to-test.md` | 利用方法、フィルター、通常テストとの違い |
| `framework/makefw/docs/build-configurations.md` | 呼び出し階層、差分ビルド、省略条件、並列度 |

表の make ファイル名のみの項目は `framework/makefw/makefiles/` 配下です。  
補助処理の名称や共通化の単位は、既存の構成に沿って実装時に決めます。  
生成済みの各 app の makefile や Google Test の配布物を手動編集しません。  
個別 app のテストに状態共有の問題が見つかった場合は、問題と影響範囲を報告し、無関係な app を一括修正しません。  
スキルや Git の管理状態は変更対象に含めません。

## 局所検証で動作と通常 test への影響を確認します

Table: test-quick の局所検証と受入条件

| 検証対象 | 受入条件 |
| --- | --- |
| 対象と起動回数 | 有効ケースとパラメーター付きケースをまとめて実行し、ケースごとの起動に戻らない |
| 差分ビルド | 未ビルド、ソース変更後、変更なしの呼び出しで必要なビルドだけを行い、ビルド失敗時に実行しない |
| フィルター | 各言語の構文が伝わり、一致・不一致・空文字・除外を確認。正常な 0 件は表示して成功 |
| 成否伝播 | assertion 失敗、起動不能、異常終了を非 0 で返し、後続の成功で上書きしない |
| 継続と並列度 | 残りの実行ファイルを実行し、指定した並列度と出力順序を維持 |
| 計測データ | GCC の簡易実行分が一時領域だけへ出力され、通常用の `.gcda` と混ざらない |
| エビデンス | 新たな標準レポートを生成せず、既存結果と通常の成功スタンプの変更有無を確認 |
| 切り替え | 通常 test → test-quick → 通常 test の順で、同じビルド成果物を利用し、簡易データ・成功状態を通常結果へ流用しない |
| 省略とフック | 変更なしの成功スタンプは使わず、保証済み app と明示除外は尊重。必要なフックを実行 |
| 環境 | Linux/GCC、Windows/MSVC、空白を含む配置、日本語出力、共有ライブラリ探索を確認 |
| 依存ツール | エビデンス・カバレッジの集計ツールを起動せず、それらがなくても簡易実行できる |

スクリプトのテストは対象と同じ階層の `bin_test/` に配置します。  
制御可能な実行ファイル・プロジェクトと一時領域を使って、起動回数、生成物、失敗伝播を検証します。  
ビルドした場合は、対象範囲の内容がある `.warn` を確認します。  
Markdown は `text_style_jp.py --dry-run` の確認後に `--in-place` を実行します。

速度は同じケース・同じ環境で測定して報告します。  
通常 test の成功キャッシュによる未実行と比べず、初回ビルド、差分ビルド、テスト実行の時間を分けます。  
数値による速度向上のしきい値は設けません。

Windows 固有の動作を実行できない場合は、未検証の範囲を明示します。  
framework 全体や複数 app の全体テストは、コストを説明してユーザーの許可を得てから実施します。  
未対応の既存結果保存の不足や、別問題として判明した未対応事項が残る場合にだけ、作業全完後に `prompt/test-quick-backlog.md` を作成します。

## 実装と成果物の承認

この仕様への明確な承認を受けたあとに、対象コード・設定・利用文書の変更へ着手します。  
変更、局所検証、変更起因の失敗修正と再検証を完了し、成果物と検証結果を提示します。  
残課題があれば、その記録も提示します。  
成果物の「承認」または「完了」の宣言を受けて、一連の作業を完了します。
