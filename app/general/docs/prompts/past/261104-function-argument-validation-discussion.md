## 調査結果と判断の根拠

現行規範は、ヘッダーの配置で NULL 検査の義務を分けています。  
公開関数とライブラリ内共有関数では検査が必須であり、モジュール内共有関数とファイル内関数では呼び出し側の保証を基本とします。  
一方、整数の負値の扱いは基本ルールに別記され、内部関数への適用関係が明確ではありません。  
また、内部関数で保証を確認しにくい場合の検査は任意であり、assert は別節で禁止されています。

- [GLib: Writing GLib Applications](https://docs.gtk.org/glib/programming.html): UTF-8 の妥当性は入力時やプログラム・ライブラリ境界で検査し、各関数での再検査を省きます。文字列の長さについても文字の途中で切れないことを要求します。
- [GLib: Warnings and Assertions](https://docs.gtk.org/glib/warnings.html): 公開関数の入口でオブジェクトの種類や引数間の条件を検査します。契約違反後の状態や失敗表現は本リポジトリと異なるため、機構そのものを採用する根拠にはしません。
- [SQLite: The Use Of assert()](https://www.sqlite.org/assert.html): 内部の事前条件を assert で確認し、証明が難しい条件などには製品でも条件を評価する ALWAYS / NEVER を使います。コメントだけで保証する現行規範と同じ設計ではありません。

公開資料は前ターンで本文を確認したものです。  
これらは境界での検査と内部契約を分ける根拠になりますが、内部関数で常に検査を省略できるという証明にはなりません。  
本リポジトリのヘッダー配置による層分けと assert 不使用は、外部事例とは区別して扱います。

## 事例追加の依頼と調査

ユーザーから「事例はもう少し量を多くできないか」と依頼されました。  
事例数を増やす要求として受け付け、検査責務や assert 不使用の合意は維持します。  
GLib の 2 例と SQLite の 1 例に、次の 5 例を追加し、計 8 例を最終仕様に具体化します。  
件数は異なる検査対象と責務を比較するための構成案であり、ユーザーが指定した数ではありません。

- [Microsoft CRT の memcpy](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/memcpy-wmemcpy?view=msvc-170): コピー先容量の確保は呼び出し側の責務で、領域の重複は未定義動作です。ライブラリ内部での使用も、呼び出しの安全性を確認する条件で認める説明があります。内部での保証を具体的に確認する必要性を示します。
- [Microsoft CRT の memcpy_s](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/memcpy-s-wmemcpy-s?view=msvc-170): コピー数が 0 でない場合の NULL と容量不足を検査します。ただし、領域の重複は依然として未定義動作です。検査付き API でも検査できる範囲に限界がある例です。不正パラメーター ハンドラーを呼び、続行が許された場合にエラーを返すため、単純な結果コード方式とは区別します。
- [OpenSSL coding style の Asserts](https://openssl-library.org/policies/technical/coding-style/): 回復可能な内部の異常には ossl_assert とエラー返却を使う設計です。debug での異常終了と release での条件評価・エラー処理が異なるため、本規範の検出機構とは区別します。
- [zlib の使用例](https://zlib.net/zlib_how.html) と [zlib マニュアル](https://zlib.net/manual.html): 不正な圧縮データの Z_DATA_ERROR とストリーム状態の Z_STREAM_ERROR を区別します。公式例は呼び出し条件から起こらないとする失敗には assert を使います。外部データの検査と内部契約の確認を分ける例です。
- [Linux の refcount 実装](https://github.com/torvalds/linux/blob/master/include/linux/refcount.h) と [警告・飽和処理](https://github.com/torvalds/linux/blob/master/lib/refcount.c): 参照カウントのオーバーフローや不正な減算に対して、警告と飽和などの防御を残します。内部処理でも新たな演算や状態遷移の異常を防ぐ例であり、本規範に同じ警告・飽和方式を導入する提案ではありません。
