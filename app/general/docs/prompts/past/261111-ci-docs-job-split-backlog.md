## BL-001 テストのビルドと実行の時間の短縮

分離後の実行 42930377100 では、最も長いジョブが OL9 のレグ (218[分]) になりました。Windows のジョブは 202[分]、OL8 のレグは 177[分] です。  
実行全体の時間は、これらのジョブで決まります。ドキュメント生成を分離した効果は、この実行では約 27[分] でした。

分離前の OL8 のログでは、cplat の 124[分] のうち、`prod` のコンパイルとリンクは 172 件 (今回の `make gen` では 18[秒]) で、大半が `test` 側でした。  
さらに短縮するには、テストのビルドと実行を複数のジョブへ分ける、またはテストのビルド時間を減らす検討が必要です。  
同じコミットでも、OL のレグの時間は 120[分] から 218[分] まで開きがあります。原因は確認していません。

### 対処の記録 (BL-001)

`ci.yml` で `MAKEFW_CPU_BUDGET` を 8 に指定し、ビルドとテストの並列度を 2 から 4 に上げました (コミット `9117efb7`)。あわせて、`app/general/docs/prompts/` 配下だけを変更するコミットに `[skip ci]` を付ける運用を定めました。  
実行 43102328935 では全ジョブが成功しましたが、短縮の効果は実行ごとの差と区別できず、実行全体は 297[分] に延びました。  
ユーザーの判断により、指定を残したまま、複数回の実走の後に評価します。評価、ジョブの分割、コンパイル結果のキャッシュは、後継の残課題一覧の BL-001 から BL-004 に引き継ぎました。

## BL-003 生成漏れの照合の対象範囲

`verify-gen` ジョブは、`app/*/prod` 配下の `gen/` ディレクトリにある C/C++ のソースとヘッダーの一覧を比べます。次の 2 つは対象に含めていません。

- `gen/` 以外の場所へ生成されるソース
- Windows だけで生成されるソース (`mc.exe` の出力)。`docs` ジョブは Linux で動くため、Doxygen の入力にも含まれません。この点は分離前と同じです。

現在の app には、`gen/` 以外へ生成するものは確認していません。新しい生成規則を追加する場合は、生成先を `gen/` に置く必要があります。

### 対処の記録 (BL-003)

「生成ソースは `$(GENDIR)` (`gen/`) に置く」という規則を、`framework/makefw/docs/build-configurations.md` の「生成ソースだけを作る (make gen)」に記載しました (makefw のコミット `56c0f49`)。照合の仕組みは変えていません。

## BL-004 cc がない Windows PC での test_ident_batch の失敗

`framework/makefw/bin_test/` の `test_ident_batch` の 2 件は、`cc` コマンドを直接呼びます。`cc` がない Windows PC では失敗します。  
今回変更したファイルを読み込まないテストであり、今回の変更とは無関係です。CI のジョブは Linux、Windows ともに成功しています。  
手元で makefw の `bin_test/` 全体を実行する場合に、失敗の切り分けが必要になります。

### 対処の記録 (BL-004)

`cc` が `PATH` に見つからない場合は、`cc is not found` の理由で 2 件をスキップするようにしました (makefw のコミット `56c0f49`)。  
`make bin-test` は、既存の規範どおり、このスキップを想定外のスキップとして失敗にします。`BIN_TEST_ARGS=--allow-skips` を指定した場合は、失敗にしません。CI では `cc` があるため、テストは実行されて成功しています。
