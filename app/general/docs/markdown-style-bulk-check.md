# Markdown 一括スタイル確認

## 前提

この手順は、第一者管理の Markdown 全体へ `text_style_jp.py` を適用するときに使用します。  
自動生成物、外部 OSS、未追跡ファイルは対象外です。

開始前に、ルートと全サブモジュールの Git 状態を記録します。  
読み取り確認は既存差分があっても実行できます。  
一括変更では対象と既存差分の重なりを確認し、依頼に含まれない変更を巻き込むファイルだけ保留します。  
自分が今回の依頼で作成した差分は、その依頼の範囲で整形できます。

## 対象の列挙

ルート Git と `.gitmodules` に登録された各 Git ルートの `git ls-files -z '*.md'` を使用します。  
固定の app 一覧をスクリプトへ埋め込まず、新しいサブモジュールも自動的に対象へ含めます。

次の外部配布物は除外します。

- `framework/docsfw/bin/modules/LibDeflate/`
- `framework/docsfw/styles/widdershins/`
- `framework/testfw/gtest/`
- app 配下で展開された第三者ソースとその生成文書

## 実行順

1. NUL 区切りで対象一覧を作成します。
2. 全対象へ `--dry-run` を実行します。
3. 差分候補を読み、日本語として不自然な変換がないことを確認します。
4. 一括変更が依頼され、問題がなければ、保留ファイルを除く同じ対象一覧へ `--in-place` を実行します。読み取り確認だけの場合は結果を報告します。
5. 各 Git ルートの差分を確認します。

`--check` だけでは全角罫線文字を検出できないため、`--dry-run` を省略しません。

## 差分の確認

- インライン コード、URL、ファイル パスの意味が変わっていないことを確認します。
- 一文の途中に表示幅調整用の改行がないことを確認します。
- リスト、表、引用、コード フェンスが崩れていないことを確認します。
- 変換すべきでない語や不自然なカタカナ分割が提案された場合は適用しません。
- 全角罫線文字は ASCII 記号へ置き換えます。

最後に `git diff --check` を実行します。  
強制改行用の半角空白 2 個は意図的な Markdown 構文として扱います。
