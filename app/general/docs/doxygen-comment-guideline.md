# app 向け Doxygen コメント

## 正本の分担

この文書は、app 配下の C/C++ コードに Doxygen コメントを配置する際の規則を示します。  
Doxygen タグの仕様は [コマンド解説](../../../framework/doxyfw/docs/commands.md)、コメント雛形は [チート シート](../../../framework/doxyfw/docs/cheatsheet.md) を正本とします。

## コメントの配置

### 公開 API と内部共有 API

- **公開要素の説明**: 公開関数、公開型、公開マクロの説明は、利用者が参照する公開ヘッダー (`prod/include/`) へ記載します。
- **内部共有要素の説明**: 複数ソース間で共有する内部 API は、内部共有ヘッダー (`prod/include_internal/`) へ記載します。
- **重複の禁止**: 宣言側 (ヘッダー) に説明がある関数は、定義側 (ソース) へ同じ Doxygen コメントを複製しません。

### 定義側の誘導マーカー

宣言側に説明がある公開関数や内部共有関数は、二重ドキュメント化を防ぐため、定義の直前に関数ごとに以下のマーカーを配置します。

```c
/* Doxygen コメントは、ヘッダーに記載 */

int sample_func(void)
```

- **配置単位**: ファイル先頭に 1 箇所だけ置くのではなく、各関数の定義前へ個別に配置します。
- **空行の確保**: マーカーと関数定義の間に空行を 1 行設けます (エディターがマーカーを関数のホバー説明として誤認することを防ぐため)。
- **先行宣言のない関数**: 先行宣言のないファイル内関数や static 関数にはマーカーを置きません。先行宣言のない関数をドキュメント化する場合は、定義直前に Doxygen コメントを記述します。

### 静的関数とファイル内シンボル

- static 関数やファイル内共有変数には、保守に必要な契約事項のみを定義側へ記載します。関数名から役割が自明な処理にコメントを追加する必要はありません。
- ファイル内スコープの `static` 変数、関数、固定テーブルに言及する場合は、未解決参照による警告を防ぐため、`@ref` ではなくバッククォート (例: `` `s_items` ``) で表記します。

## 参照できるシンボルの範囲

`@see` や `@ref` でシンボルへのリンクを生成する場合は、参照先が同一の Doxygen 生成単位 (対象 Doxyfile の `INPUT`) に含まれていることを確認します。

- **別 app のシンボルへの言及**: 別の生成単位に属する API 名や結果コード (例: `` `CPLAT_OK` ``) は、`@ref` ではなくバッククォートによるコード表記を用います。
- **Web リンク**: 外部ページや別 app の公開ドキュメントへリンクする場合は、`@see` に直接 URL を指定します。
- **tag file の連携**: シンボル名から別の生成単位の文書へ直接リンクを作成する場合は、参照先の tag file と文書パスを `TAGFILES` に設定します (詳細は [Doxygen の外部文書リンク (英語)](https://www.doxygen.nl/manual/external.html) を参照)。

## 本文の記述規則

### 文体と概要

- **文体**: Doxygen コメント本文は「です・ます」調で記載します。
- **@brief の役割**: 対象の責務を一文で明確に説明します。「〜の実装ファイルです」のような形式的な説明は避けます。

### Markdown 表の記法

- **キャプションの付与**: コメント内の Markdown 表には、内容を示す `Table:` キャプションを必ず付けます (詳細は [表のキャプション](../../../framework/docsfw/docs/table-caption.md) を参照)。
- **空行の挿入**: 表と `Table:` 行の間、および `Table:` 行と後続のテキスト・タグ・見出しの間には、アスタリスクだけの空行 (` *`) を挿入します。
- **段落ブロック化 (`@parblock`)**: `@par` 見出しの配下に表を配置する場合、空行によって段落が途切れないよう、見出しブロック全体を `@parblock` と `@endparblock` で囲みます。

### 箇条書きのインデント

- **開始位置**: リスト記号 (`-`) は、コメント本文と同じ桁に置くか、直前の文の次の行へ空行なしで配置します。
- **ネストの深さ**: 子項目は親項目より 4 スペース深くインデントします。

### 引数・戻り値・契約事項の記載

- **方向タグの明示**: 引数には `@param[in]`、`@param[out]`、`@param[in,out]` を使用します。
- **全引数の網羅**: 関数に Doxygen コメントを付与する場合は、すべての仮引数に対して `@param` を漏れなく記載します (記載漏れがあると Doxygen が警告を出力します)。
- **契約の明記**: NULL ポインターの許容可否、バッファー サイズ、所有権、戻り値の意味、スレッド安全性を明記します。
- **スレッド安全性の見出し**: スレッド安全性に関する記述は、[コーディング規範](coding-guideline.md) に従い `@par            スレッド セーフ` で統一します (`スレッド安全性` などの表記揺れを用いません)。
- **修飾子の整合**: 宣言と定義の修飾子、`const`、方向タグは [コーディング規範](coding-guideline.md) と完全に一致させます。

## 整形と生成確認

- **ファイル コメントの枠線**: ファイル先頭の `@file` ブロックの前後に、79 文字のアスタリスク セパレータ (` *******************************************************************************`) を配置します。
- **タグの桁揃え**: タグ (`@file`、`@brief`、`@param[in]`、`@retval`、`@par` など) は、開始位置から 16 桁幅で説明や引数名を揃えます。
- **生成確認**: タグ、参照、公開契約、Doxyfile、出力構造を変更した場合は、対象 app で `make doxy` を実行し、警告ログ (`.warn`) と生成結果を確認します。
- **生成物の直接編集禁止**: `doxyfw` が出力した生成物 (Doxybook2 Markdown 等) は直接編集しません。修正が必要な場合は、生成元であるヘッダー、ソース、Doxyfile、または変換スクリプトを修正します。
