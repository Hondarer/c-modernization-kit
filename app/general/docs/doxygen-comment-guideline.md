# app 向け Doxygen コメント

## 正本の分担

この文書は、app の C/C++ コードで Doxygen コメントを配置するときの規則を示します。  
Doxygen タグの意味は [コマンド解説](../../../framework/doxyfw/docs/commands.md)、雛形は [チート シート](../../../framework/doxyfw/docs/cheatsheet.md) を正本とします。

## コメントの配置

公開関数、公開型、公開マクロの説明は、利用者が読む公開ヘッダーへ記載します。  
複数のソースから共有する内部 API は内部共有ヘッダーへ記載します。  
宣言側に説明がある関数は、定義側へ同じ説明を複製しません。

宣言側に説明がある公開関数や内部共有関数は、定義の直前へ次のマーカーを関数ごとに置きます。  
ファイル先頭や先頭の関数へ一度だけ置くのではなく、各関数の定義前へ個別に配置します。  
先行宣言のないファイル内関数や static 関数には置きません。  
先行宣言のない関数へ Doxygen コメントを付与する場合は、マーカーを置かず定義直前に Doxygen コメントを配置します。

```c
/* Doxygen コメントは、ヘッダーに記載 */

int sample_func(void)
```

マーカーと関数定義の間の空行は、エディターがマーカーを関数のホバー説明として扱うことを避けるために必要です。

static 関数やファイル内共有変数には、保守に必要な契約だけを定義側へ記載します。  
自明な処理を関数名から言い換えただけのコメントは追加しません。  
ファイル内スコープの `static` 変数、関数、固定テーブルを参照する場合は、未解決参照による Doxygen 警告を防ぐため、`@ref` ではなくバッククォート (例: `` `s_items` ``) を使用します。

## 参照できるシンボルの範囲

`@see` や `@ref` でシンボルへのリンクを作る場合は、参照先が同じ Doxygen 生成単位 (対象の Doxyfile の `INPUT`) に含まれるか確認します。  
このワークスペースの既定設定では、別の Doxygen 生成単位の tag file を `TAGFILES` に登録していません。  
そのため、別 app など別の生成単位に属するシンボルは、名前だけでは解決できず未解決参照警告の原因になります。  
別の生成単位の API 名や結果コード (例: `` `CPLAT_OK` ``) に言及する場合は、バッククォートでコードとして表記します。  
別の生成単位の公開ページや一般の Web ページへリンクする場合は、`@see` に URL を指定できます。  
シンボル名から別の生成単位の文書へリンクする場合は、参照先の tag file と文書の場所を `TAGFILES` に設定します。  
外部文書を参照する設定の詳細は、[Doxygen の外部文書リンク (英語)](https://www.doxygen.nl/manual/external.html) を参照します。

## 本文

Doxygen コメントの本文は、です・ます調で記載します。  
`@brief` は対象の役割を一文で説明し、「実装ファイルです」のような種類だけの説明を避けます。

引数には `@param[in]`、`@param[out]`、`@param[in,out]` を使用します。  
関数に Doxygen コメントを付与する場合は、すべての仮引数について `@param` を漏れなく記載します。  
一部の引数だけを記載すると、Doxygen が未ドキュメント引数として警告を出力します。  
NULL の許可、所有権、バッファー サイズ、戻り値、スレッド安全性など、呼び出し側が守る契約を記載します。

宣言と定義の修飾子、`const`、方向タグは [コーディング規範](coding-guideline.md) と一致させます。

## 整形と生成確認

ソースを整形した後は、複数行コメントの `*` とタグの字下げを確認します。  
タグ、参照、公開契約、Doxyfile、出力構造を変更した場合は対象 app の `make doxy` を実行し、警告ファイルと生成結果を確認します。  
誤字や字下げだけの修正は差分確認を基本とし、レビューだけの場合は判断に必要なときに生成します。

生成済み Doxybook2 Markdown は直接編集しません。  
表示を変更する場合は、ヘッダー、ソース、Doxyfile、または doxyfw の変換処理を変更します。
