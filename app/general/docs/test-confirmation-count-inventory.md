第三者配布物と自動生成されたファイルは対象外です。

[ファイル別の棚卸し](test-confirmation-count-inventory.tsv) には、対象パス、テスト形式、定義数、確認タグ数、回数指定数を記載しました。

確認タグの個数は記載箇所の数です。  
確認件数は、回数式の評価結果を合計して算出します。  
回数指定を省略した確認タグは、テスト定義全体で 1 回として数えます。  
`[状態確認]` は表の確認タグ数にも確認件数にも含めません。  
`PARAM` は各実行環境で展開された全レコード数を用います。

## ループとヘルパーに実際の確認回数を記載

- パラメーター テストには `回数=PARAM` を記載しました。
- メモリ順序 5 種の検証、3 × 3 のフィールド型の組み合わせ、2 種の並行性モード × 16 回の生成と破棄などに回数を記載しました。
- 列挙終了を確認する呼び出しを含む正規表現の反復は `回数=3+1` としました。
- 共通ヘルパーが行う複数の確認は、呼び出し箇所の確認タグに回数式を記載しました。エクスポート照合は不足と余剰の 2 回、詳細エラーの照合はドメイン、結果コード、OS コードの 3 回です。
- 準備時の資源確認には `[状態確認]` を付け、件数から除外しました。fixture と準備用ヘルパー内の資源確認も、テスト対象の結果確認とは区別しました。
- ループ全体の説明と各 Assert の説明が重複していた箇所は、全体の説明を通常のコメントへ変更しました。
- モックのコールバック内の Assert と、後処理に登録する呼び出し期待へ `[Pre-Assert確認_*]` を付けました。`.Times(n)` は期待 1 つとして数えます。

errno の定義数が環境で異なる確認は、期待するエラー要因の一覧と実際の一覧を 1 回照合する形へ変更しました。  
表示言語が空の場合を許容する確認は、空文字列の比較も含めて 2 回の確認を常に行う形へ変更しました。  
クラッシュしないことをコメントだけで示していた箇所には `SUCCEED()` を記載して確認タグを付け、確認行為を明示しました。

## スクリプトのテストは専用コメント集計の対象外

追跡対象のスクリプトのテストと検証補助は 81 ファイルです。  
Python、JavaScript、PowerShell、シェルの検証は各テスト ランナーの集計を使い、testfw の専用コメントによる件数集計には含めません。

## 静的点検と局所テストで確認

全対象の確認タグと回数式を共通パーサーで検査しました。  
Google Test のテスト本体について、`text_style_jp.py` の検査で検出される Assert と `EXPECT_CALL` の確認コメント不足は 0 件です。  
反復と条件分岐、ヘルパー呼び出しは、アルゴリズムとテスト データから回数を確認しました。

局所テストの結果は次のとおりです。

- errno の集約確認: Linux の `errorTest` に合格
- 表示言語: Linux の `uiLanguageTest` に合格。変更した Windows 固有の分岐は未実行
- 正規表現: Linux の 48 テストに合格
- パターン定数: Linux の対象 1 テストに合格
- `SUCCEED()` を明示した確認: Linux の対象 7 テストに合格
- パラメーター テストのサンプル: Linux の 10 レコードに合格
- 共通の回数式パーサー: 18 テストに合格

リポジトリ全体のテストと Windows のテストは実行していません。  
記載した件数は、失敗による早期終了を除く、設計上の確認回数です。
