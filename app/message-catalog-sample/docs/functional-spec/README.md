# message_catalog 機能仕様

## この文書群の役割

`functional-spec/` は、利用側または上位設計から見た message_catalog の責務を、機能カテゴリごとに説明する文書群です。  
message_catalog が解決する課題、満たす要件、外部から観測できる振る舞い、前提、保証範囲、適用範囲外を定めます。

message-catalog-sample は、この機能仕様を満たすライブラリと、その利用例を示すコマンドで構成します。  
コマンドが用意するメッセージ ID の列挙とカタログの内容は、利用側の資産であり、機能仕様の対象ではありません。

## 文書の位置付け

機能仕様は、API 設計、実装設計、実装、テストへ渡す入力です。  
機能仕様より下流の成果物を根拠として、機能仕様を記載してはなりません。

機能仕様は、関数の一覧、実装方式、テスト方法を扱いません。  
下流成果物は、設計判断または検証対象の根拠を示す必要がある場合に、機能仕様の要件 ID と UUID を参照します。

## 記載規範

記載する内容、章立て、記載粒度、要件の種別、要件 ID と UUID の変更規則は、[cplat 機能仕様の記載規範](../../../c-platform/docs/functional-spec-guideline.md) に従います。  
同じ規範を本書へ複製せず、message_catalog 固有の読み替えだけを次に示します。

本文の構成と表現は、[日本語技術文書の文章規範](../../../../framework/docsfw/docs/japanese-technical-writing-guideline.md) に従います。

### 要件 ID の形式

要件 ID は、次の形式とします。

```text
MSGCAT-<CATEGORY>-<TYPE>-NNN
```

`<CATEGORY>` は、機能仕様のファイル名に対応する大文字のカテゴリ名です。  
`<TYPE>` は、`FUNC`、`QUAL`、`COMP`、`CONS` のいずれかの種別コードです。  
`NNN` はカテゴリと種別の組み合わせごとに `001` から始まる 3 桁以上の連番です。

### カテゴリごとの主語

要件文では、要件 ID のカテゴリに対応する機能を主語とし、主語を省略しません。

| カテゴリ | 主語 |
|---|---|
| `CATALOG` | message_catalog のカタログ管理機能 |
| `FORMAT` | message_catalog のメッセージ組み立て機能 |
| `LANGUAGE` | message_catalog の言語選択機能 |

### 要件と参照の記法

要件は、要件 ID の直後へ UUID を一つの HTML コメントとして記載します。  
コメントの接頭辞は `msgcat-req` とします。

```markdown
| `MSGCAT-EXAMPLE-FUNC-001` <!-- msgcat-req: uuid=123e4567-e89b-42d3-a456-426614174000 --> | ... |
```

下流成果物から参照する場合も、同じ接頭辞を使用します。

```c
/* msgcat-req: id=MSGCAT-CATALOG-FUNC-001; uuid=123e4567-e89b-42d3-a456-426614174000 */
```

要件 ID と UUID の形式を機械的に確認する仕組みは、この app には用意していません。  
追加する場合は、cplat の確認手段と同じ検査項目を対象とします。

## 変更時の扱い

message_catalog の機能、外部から観測できる振る舞い、前提、保証範囲、適用範囲外を変更する場合は、対応する機能仕様を先に変更します。  
その後、公開 API、実装、テストを機能仕様へ適合させます。
